# Agent Commons: руководство пользователя

Agent Commons — локальное веб-приложение для управления работой команды
AI-агентов. Вы формулируете работу, выбираете исполнителя, следите за
результатом и принимаете финальное решение. Продукт не принимает продуктовые
решения и не утверждает работу вместо вас.

## Как устроено рабочее пространство

Продукт построен вокруг простой цепочки:

```text
Роль → Задача → Прогон → независимое ревью → приёмка человеком
```

### Роль

**Роль** — постоянная ответственность в команде: например,
`Backend-разработчик`, `Product designer` или `Независимый ревьюер`. На экране
Work роль создаётся через название, **Профиль runtime**, короткое описание
ответственности и начальный контекст.

Выбирайте **Fresh**, когда роль должна начать без контекста предыдущей работы.
Выбирайте **Accumulated**, только если хотите, чтобы эта роль продолжала со
своим накопленным контекстом. Роль — не то же самое, что одна попытка выполнить
работу.

### Задача

**Задача** описывает, что нужно сделать и как оценить результат. В интерфейсе у
неё есть название, описание и **Критерии приёмки**. Пишите по одному понятному
результату на критерий. Небольшие проверяемые задачи проще выполнить и
проверить.

### Прогон

**Прогон** — одна ограниченная попытка роли выполнить одну задачу. Запуск
использует настроенный на вашем компьютере локальный провайдер Claude или
Codex. Он может расходовать ваш аккаунт или подписку провайдера так же, как
прямой запуск этого провайдера.

Завершённый прогон не делает задачу принятой. Он сообщает только исход попытки.
У одной задачи может быть несколько прогонов.

### Ревью и приёмка

**Ревью** — оценка работы независимым человеком или ролью. Оно привязано к
конкретной версии задачи. **Приёмка** — ваша записанная фиксация, что
проверенную работу можно использовать.

Это важное различие: успешный прогон не является одобрением, а ревью старой
версии задачи нельзя использовать после её редактирования.

### Внимание и блокировки

Полная панель помечает элементы, которые **ждёт вас** — ждут вашего
действия. Блокировка означает, что агент, прогон, задача или ревью не могут
двигаться дальше без решения или исправления. Откройте элемент и выполните
следующее доступное действие. Заблокированная работа не считается завершённой.

## Как безопасно открыть приложение

В исходном checkout Agent Commons выполните:

```bash
make sync
uv run agent-commons ui
```

Приложение работает только на вашем компьютере и выводит локальный URL. Команда
может открыть браузер по умолчанию. Этот адрес содержит короткоживущий
одноразовый код входа.

- Открывайте напечатанный URL только один раз.
- Если нужен определённый браузер, запустите
  `uv run agent-commons ui --no-browser`, затем один раз откройте в нём новый
  напечатанный адрес.
- Если браузер сообщает, что сессия больше не активна, остановите локальный UI,
  запустите его заново и один раз откройте новый адрес. Старый адрес не
  восстановит сессию.

Не передавайте локальный URL другим людям, пока панель запущена. Он даёт
браузеру доступ к этой локальной панели, а не создаёт ссылку для совместной
работы.

## Как настроить рабочее пространство и runtime

UI работает с Git-репозиторием, из которого он был запущен. Выбрать другой
проект внутри браузера нельзя. Перед нажатием **Инициализировать рабочее
пространство** убедитесь, что терминал открыт в нужном проекте.

### 1. Инициализируйте рабочее пространство

Если экран Work показывает **Файлы рабочего пространства ещё не созданы**,
нажмите **Инициализировать рабочее пространство**. Agent Commons создаст файлы
рабочего пространства в текущем репозитории. Если написано, что папка не
является Git-репозиторием, сначала выберите или создайте Git-репозиторий, затем
перезапустите UI.

### 2. Настройте runtime

Чтобы роль могла начать работу, нужен локальный runtime провайдера. Нажмите
**Настроить runtime**, когда эта кнопка доступна. Настройка проверяет локально
установленные Claude или Codex и записывает только сгенерированную
конфигурацию.

Если провайдер не найден, установите и авторизуйте CLI одного из провайдеров в
своём аккаунте, затем вернитесь в панель и обновите статус. Текущий экран Work
может не объяснить точную локальную причину: если следующее действие неясно,
используйте полную панель или [техническое руководство по устранению
проблем](../../TROUBLESHOOTING.md).

Не редактируйте сгенерированные runtime-файлы через браузер: в текущем UI нет
редактора конфигурации. Для особой настройки используйте техническую
документацию для операторов.

## Как создать роль и задачу

### Создайте роль

В блоке **2. Создайте роль**:

1. Заполните **Название роли**.
2. Выберите **Профиль runtime**.
3. Укажите, **За что отвечает эта роль**.
4. Выберите **Начальный контекст**: **Fresh** или **Accumulated**.
5. Нажмите **Создать роль**.

Профиль определяет, как эта роль может запускаться. Если форма сообщает, что
доступных профилей runtime пока нет, завершите настройку runtime до создания
роли.

### Создайте задачу

В блоке **3. Опишите задачу**:

1. Дайте задаче короткое **Название задачи**.
2. Опишите, **Что нужно сделать**, и важные ограничения.
3. Добавьте **Критерии приёмки** — по одному результату в строке.
4. Нажмите **Создать задачу**.

Задача намеренно отделена от роли. При запуске прогона вы решаете, какая
активная роль будет над ней работать.

## Как запустить и контролировать прогон

В блоке **4. Запустите прогон** выберите роль и задачу, затем нажмите
**Запустить прогон**. Роль должна быть активной, а runtime — настроенным.

После успешного запуска экран Work сообщает **Прогон запущен** и предлагает
**Открыть старую панель**. Это текущая граница сценария:

- экран Work предназначен для настройки, создания ролей и задач и запуска
  одного прогона;
- полная панель предназначена для подробного мониторинга, раздела **Прогоны**,
  ревью, приёмки и восстановления.

В полной панели прогон может быть requested, active, succeeded, failed, timed
out или `needs_operator`. `needs_operator` означает, что продукт не может
безопасно продолжить без вас. Сначала изучите прогон, а уже потом повторяйте
его или создавайте новый: это не успешный результат.

## Как проверить и принять выполненную работу

Этот этап выполняется в полной панели.

1. Откройте задачу, когда её работа готова.
2. Нажмите **Отправить на ревью**. Задача начнёт ждать независимое ревью.
3. Запустите или попросите независимого ревьюера проверить эту задачу. Тот, кто
   выполнял работу, не может дать независимое ревью, необходимое для приёмки.
4. Если вердикт одобрен и относится к текущей версии задачи, откройте задачу,
   нажмите **Принять…**, заполните **Что именно вы принимаете?**, затем нажмите
   **Записать приёмку**.

Если ревью нашло проблему, выберите **Вернуть в работу…**, объясните причину
и дайте команде доработать задачу или результат. Редактирование задачи создаёт
новую версию и делает прежние ревью устаревшими. Новую версию нужно снова
отправить на ревью.

Панель откажет в прямой приёмке, если нет актуального одобренного независимого
ревью. Это защита процесса, а не ошибка интерфейса.

### Как читать состояние задачи

В зависимости от хода работы задача может отображаться как `ready`, `assigned`,
`active`, `completed`, `review`, `accepted`, `blocked` или `cancelled`. Это
текущий шаг работы, а не оценка качества. В частности, `completed` означает,
что автор сообщил о готовности; до `accepted` всё ещё нужно ревью. `blocked` и
`cancelled` не показывают действие отправки на ревью в карточке задачи.

### Используйте полную панель для работы команды

На **Доске** полной панели видны роли, задачи и связи между ними. Во вкладке
**Внимание** разбирайте то, что ждёт человека; в **Прогонах** смотрите попытки;
**Общий чат** используйте для разговора, который сам по себе не является
задачей. В **Каталоге ролей** можно повторно использовать сохранённый шаблон
роли. Шаблон ускоряет наём, но не меняет конфигурацию локального провайдера.

Открывайте **Настройки** задачи, только если действительно хотите создать новую
версию. UI предупреждает, что прежние ревью станут устаревшими; обновлённую
задачу нужно проверить заново.

## Как разбираться с блокировками и проблемами

| Что вы видите | Что это значит | Что делать |
| --- | --- | --- |
| **Сессия этого браузера больше не активна** | Одноразовая локальная ссылка уже использована или устарела. | Перезапустите UI и один раз откройте новый напечатанный адрес в нужном браузере. |
| **Файлы рабочего пространства ещё не созданы** | Этот репозиторий ещё не инициализирован для Agent Commons. | Убедитесь, что терминал открыт в нужном Git-репозитории, затем нажмите **Инициализировать рабочее пространство**. |
| **Конфигурация runtime ещё не создана** или **Runtime ещё не готов начать работу** | Нет пригодного локального runtime провайдера. | Настройте runtime; если проблема осталась, установите/авторизуйте Claude или Codex и обновите статус. |
| **Пока нет доступных профилей runtime** | В настроенном runtime нет профиля, который можно выбрать. | Проверьте конфигурацию в полной панели или техническом руководстве оператора. |
| **ждёт вас** | Прогон, задача, ревью или вопрос ждёт человеческого решения. | Откройте связанный элемент и сделайте следующий шаг, который показывает UI. |
| `needs_operator` | Продукт получил исход, который не может безопасно разрешить сам. | Изучите прогон и задачу в полной панели. Не считайте работу успешной и не повторяйте её вслепую. |
| Приёмка отклонена | Нет актуального одобренного независимого ревью или задача изменилась после ревью. | Отправьте текущую версию задачи на независимое ревью и принимайте её только после одобрения. |

Если страница временно недоступна, обновите её один раз. Если проблема
повторяется, заново откройте локальный UI по новому адресу и используйте полную
панель для восстановления. Не вставляйте в баг-репорт вывод провайдера,
промпты, учётные данные или локальный URL входа.

## Границы текущей версии

Agent Commons — alpha-версия для macOS и Linux. Он работает с локальными
инструментами провайдеров; Windows пока не поддерживается. Runtime провайдера
экспериментальный и может потребовать решения оператора.

Сейчас у продукта две связанные UI-поверхности, а не один завершённый экран:
Work начинает работу, а полная панель завершает операционный цикл. Нативных
экранов Work для прогонов, ревью, приёмки, визуальных дизайн-артефактов,
наследования контекста или автоматического планирования в этой версии нет,
если интерфейс явно не показывает обратное.

Продукт фиксирует координацию и решения. Он сам по себе не даёт право
коммитить, пушить, деплоить, публиковать, связываться с людьми или выполнять
другие внешние действия.
