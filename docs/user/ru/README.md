# Agent Commons: руководство пользователя

Agent Commons — локальное веб-приложение для управления работой команды
AI-агентов. Вы формулируете работу, выбираете исполнителя, следите за
результатом и принимаете финальное решение. Продукт не принимает продуктовые
решения и не утверждает работу вместо вас.

## Как устроено рабочее пространство

Продукт построен вокруг простой цепочки:

```text
Задача → выбор агента → Прогон → независимая проверка (review) → приёмка
```

Проект открывается на **Доске**. Каждый нанятый агент — это карточка,
записанная связь между агентами — стрелка, а применение шаблона проекта
рисует его агентов и задачи внутри рамки отдела. Расстановка карточек и рамок
— ваша раскладка: она не меняет задачи, прогоны, проверки и приёмку. Трекер
задач находится во вкладке **Задачи**.

### Агент

**Агент** — постоянная ответственность в команде: например,
`Backend-разработчик`, `Product designer` или `Независимый ревьюер`. В разделе
**Агенты** агент нанимается через название, **Профиль runtime**, короткое
описание ответственности и начальный контекст; нанять его можно и из боковой
панели Доски. В журнале и формах эта запись называется ролью, поэтому слово
«роль» остаётся в интерфейсе и технических деталях.

Выбирайте **Fresh** для изолированного старта. **Accumulated** требует при
запуске одну точную актуальную ревизию Context Pack. Передаётся этот
ограниченный контекст, а не предыдущий разговор с провайдером. Его происхождение
остаётся видимым при проверке. Агент — не то же самое, что одна попытка
работы.

### Задача

**Задача** описывает, что нужно сделать и как оценить результат. В интерфейсе у
неё есть название, описание и **Критерии приёмки**. Пишите по одному понятному
результату на критерий. Небольшие проверяемые задачи проще выполнить и
проверить.

### Прогон

**Прогон** — одна ограниченная попытка агента выполнить одну задачу. Запуск
использует настроенный на вашем компьютере локальный провайдер Claude, Codex
или Grok Build. Он может расходовать ваш аккаунт или подписку провайдера так же, как
прямой запуск этого провайдера.

Завершённый прогон не делает задачу принятой. Он сообщает только исход попытки.
У одной задачи может быть несколько прогонов.

### Проверка и приёмка

**Проверка (review)** — оценка работы независимым человеком или агентом. Она
привязана к конкретной версии задачи. **Приёмка** — ваша записанная фиксация,
что проверенную работу можно использовать.

Это важное различие: успешный прогон не является одобрением, а проверка старой
версии задачи нельзя использовать после её редактирования.

### Внимание и блокировки

Во вкладке **Задачи** выберите фильтр задач, требующих внимания, и откройте
задачу: инспектор покажет следующий шаг и то, что ждёт вашего действия.
Блокировка означает, что агент, прогон, задача или проверка не могут
двигаться дальше без решения или исправления. Откройте элемент и выполните
следующее доступное действие. Заблокированная работа не считается завершённой.

## Как безопасно открыть приложение

В исходном checkout Agent Commons выполните:

```bash
make sync
uv run agent-commons ui
```

Приложение работает только на вашем компьютере и выводит локальный URL. Команда
может открыть браузер по умолчанию. Этот адрес содержит короткоживущий
одноразовый код входа.

- Открывайте напечатанный URL только один раз.
- Если нужен определённый браузер, запустите
  `uv run agent-commons ui --no-browser`, затем один раз откройте в нём новый
  напечатанный адрес.
- Если браузер сообщает, что сессия больше не активна, остановите локальный UI,
  запустите его заново и один раз откройте новый адрес. Старый адрес не
  восстановит сессию.

Текущий текст ошибки может предлагать ещё раз открыть напечатанный адрес. Не
используйте это как способ повторно применить уже использованный или устаревший
код: перезапустите локальный UI и используйте новый адрес.

Не передавайте локальный URL другим людям, пока панель запущена. Он даёт
браузеру доступ к этой локальной панели, а не создаёт ссылку для совместной
работы.

## Как настроить рабочее пространство и runtime

Репозиторий запуска становится первым проектом. Выбирайте другие в разделе
**Проекты** слева. У каждого проекта своя команда, задачи, дизайн-галерея и
история прогонов; определения навыков и шаблонов проектов общие для сервиса.

Нажмите **Новый проект**, укажите имя и абсолютный путь рабочей папки, затем
проверьте папку и подтвердите создание. Для готового репозитория выберите
подключение существующего. Новый проект открывает свою библиотеку шаблонов:
примените шаблон или откройте **Доску**, чтобы начать с пустого проекта.
Создание проекта само по себе не запускает провайдера.

При переключении черновики задач и библиотеки сохраняются раздельно в памяти
браузера. Перезагрузка или закрытие страницы очищает несохранённые черновики.
Прогоны продолжаются, пока работает локальный сервис. В **Действиях с проектом**
доступны переименование, архивирование и восстановление; архив не удаляет файлы
и не останавливает прогон.

Если инициализация прервалась и её результат неоднозначен, сохраните путь,
вернитесь назад и явно проверьте/подключите существующий репозиторий. Приложение
не присваивает появившийся workspace исходному запросу автоматически. Для
прежнего входа в один проект оператор может использовать `ui --single-project`.

### 1. Инициализируйте рабочее пространство

Откройте **Настройки**. Если показано **Файлы рабочего пространства ещё не созданы**,
нажмите **Инициализировать рабочее пространство**. Agent Commons создаст файлы
рабочего пространства в текущем репозитории. Если написано, что папка не
является Git-репозиторием, сначала выберите или создайте Git-репозиторий, затем
перезапустите UI.

### 2. Настройте runtime

Чтобы агент мог начать работу, нужен локальный runtime провайдера. Нажмите
**Настроить runtime** в **Настройках**, когда эта кнопка доступна. Настройка проверяет локально
установленные Claude, Codex или Grok Build и записывает только сгенерированную
конфигурацию.

Если провайдер не найден, установите и авторизуйте CLI одного из провайдеров в
своём аккаунте, затем вернитесь в панель и обновите статус. Экран настроек
может не объяснить точную локальную причину: если следующее действие неясно,
откройте [техническое руководство по устранению
проблем](../../TROUBLESHOOTING.md) или попросите оператора проверить runtime
из терминала.

Не редактируйте сгенерированные runtime-файлы через браузер: в текущем UI нет
редактора конфигурации. Для особой настройки используйте техническую
документацию для операторов.

## Как создать агента и задачу

Начните с задачи; команду можно подготовить перед первым прогоном.

### Наймите агента

В разделе **Агенты** откройте форму найма или наймите агента из боковой панели
Доски:

1. Заполните **Название роли**.
2. Выберите **Профиль runtime**.
3. Укажите, **За что отвечает эта роль**.
4. Выберите **Начальный контекст**: **Fresh** или **Accumulated**.
5. Нажмите **Создать роль**.

Профиль определяет, как этот агент может запускаться. Если форма сообщает, что
доступных профилей runtime пока нет, завершите настройку runtime до найма.

### Создайте задачу

Откройте вкладку **Задачи** и нажмите **Новая задача**:

1. Дайте задаче короткое **Название задачи**.
2. Опишите, **Что нужно сделать**, и важные ограничения.
3. Добавьте **Критерии приёмки** — по одному результату в строке.
4. При необходимости выберите задачи-предшественники.
5. Нажмите **Создать задачу**. Её детали откроются автоматически.

Задача намеренно отделена от агента. При запуске прогона вы решаете, какой
активный агент будет над ней работать.

## Как запустить и контролировать прогон

Выберите готовую задачу во вкладке **Задачи**, затем действие подготовки
прогона. Задача уже выбрана. Укажите активного агента и пресет, задайте лимит
времени попытки в целых минутах от 1 до 60, проверьте бюджет и требования к
Context Pack или Design Package, затем явно нажмите **Запустить прогон**.
Создание задачи не запускает провайдера. Проверки готовности и зависимостей
могут запрещать запуск даже при записанном состоянии `ready`.

Инспектор задачи показывает цель, зависимости, историю прогонов и следующее
доступное действие. В технических деталях доступны точные идентификаторы
и ревизии.

Прогон может быть requested, active, `input_needed`, succeeded, failed,
timed out или `needs_operator`. `input_needed` означает, что прогон задал
человеку вопрос. Текущий безголовый runtime не может передать ответ, поэтому
прогон завершается как `needs_operator`. `needs_operator` означает, что продукт
не может безопасно продолжить сам: изучите прогон в инспекторе задачи,
устраните причину и запустите новый прогон. Это не успешный результат.

## Как проверить и принять выполненную работу

Используйте действия выбранной задачи во вкладке **Задачи**. Проверка
и приёмка относятся к точной ревизии задачи.

1. Откройте задачу, когда её работа готова.
2. Нажмите **Запросить проверку**. Задача начнёт ждать независимую проверку.
3. Запустите или попросите независимого ревьюера проверить эту задачу. Тот, кто
   выполнял работу, не может дать независимую проверку, необходимую для
   приёмки.
4. Если вердикт одобрен и относится к текущей версии задачи, откройте задачу,
   заполните **Сводку приёмки**, затем нажмите **Принять точную редакцию
   задачи**.

Если проверка нашла проблему, укажите **Причину новой редакции**, подтвердите
повторное открытие и нажмите **Переоткрыть задачу**. Дайте команде доработать
задачу или результат. Редактирование задачи создаёт
новую версию и делает прежние проверки устаревшими. Новую версию нужно снова
отправить на проверку.

Панель откажет в прямой приёмке, если нет актуальной одобренной независимой
проверки. Это защита процесса, а не ошибка интерфейса.

### Как читать состояние задачи

В зависимости от хода работы задача может отображаться как `ready`, `assigned`,
`active`, `completed`, `review`, `accepted`, `blocked` или `cancelled`. Это
текущий шаг работы, а не оценка качества. В частности, `completed` означает,
что автор сообщил о готовности; до `accepted` всё ещё нужна проверка.
`blocked` и `cancelled` не показывают действие отправки на проверку в карточке
задачи.
Полнота данных evidence не означает, что задача выполнена или принята.
Готовность к запуску показана отдельно от состояния задачи. Неизвестные или
устаревшие данные не дают права запускать или принимать работу.

### Как повторно использовать шаблоны, контекст и дизайн

Откройте **Библиотеку**: в ней есть 30 специализаций, 45 навыков по группам
и семь встроенных шаблонов проектов. Навыки, специализации и собственные
шаблоны можно создавать и обновлять в UI; группы навыков можно архивировать
и восстанавливать. Шаблон создаёт агентов и задачи по описанию проекта и
ничего не запускает; его подтверждение ведёт к **подготовке прогона** первой
готовой задачи. Вкладка **Контекст** хранит исходные сведения и ограничения
проекта. См. [руководство по библиотеке и графу](service-library.md).

Во вкладке контекста используйте обычный редактор: краткое содержание, факты
с точными ссылками на источники, решения и открытые вопросы. Выбор источника
показывает допустимые метаданные, а не содержимое источника. Обновление списка
не заменяет уже выбранную ревизию. Недоступную или устаревшую ссылку нужно
исправить до публикации. Расширенный редактор сохраняет структурированный JSON.

Откройте **Результаты** у задачи или нанятого агента, если есть доступные
результаты. Здесь показаны изображения и отдельные live-превью этого агента
с пометками: последняя версия, более ранняя версия, превью устарело, адрес
недоступен или результат ждёт проверки; вкладки дизайна в Библиотеке нет.
Design Package выбирается явно при подготовке прогона; доступ и актуальность
проверяются повторно. Просмотр пакета не
прикрепляет его к задаче или прогону автоматически.

Откройте **Обсуждение** для сообщений проекта либо у задачи или агента для
этой области. Там видны доступность получателя и шаги доставки. Отправка
сообщения не запускает модель и не доказывает, что агент его прочитал.
Состояния доставки, приватные вложения и восстановление черновиков описаны
в [руководстве по общению и
результатам](service-library.md#общаться-и-смотреть-результаты).

### Смотрите команду и меняйте задачу

На **Доске** видны агенты, записанные связи между ними и рамки отделов,
созданные шаблоном проекта. Нанимать можно из боковой панели, а карточка
агента ведёт к его задачам. Вкладка **Задачи** показывает ту же работу графом
и списком; её инспектор хранит историю прогонов и следующее доступное
действие. Сохранённая специализация в **Библиотеке** ускоряет наём, но не
меняет конфигурацию локального провайдера.

Чтобы изменить задачу, откройте её во вкладке **Задачи** и выберите **Изменить
задачу**. Сохранение создаёт новую версию. UI предупреждает, что прежние
проверки станут устаревшими; обновлённую задачу нужно проверить заново.

## Как разбираться с блокировками и проблемами

| Что вы видите | Что это значит | Что делать |
| --- | --- | --- |
| **Сессия этого браузера больше не активна** | Одноразовая локальная ссылка уже использована или устарела. | Перезапустите UI и один раз откройте новый напечатанный адрес в нужном браузере. |
| **Файлы рабочего пространства ещё не созданы** | Этот репозиторий ещё не инициализирован для Agent Commons. | Убедитесь, что терминал открыт в нужном Git-репозитории, затем нажмите **Инициализировать рабочее пространство**. |
| **Конфигурация runtime ещё не создана** или **Runtime ещё не готов начать работу** | Нет пригодного локального runtime провайдера. | Настройте runtime; если проблема осталась, установите/авторизуйте Claude, Codex или Grok Build и обновите статус. |
| **Пока нет доступных профилей runtime** | В настроенном runtime нет профиля, который можно выбрать. | Попросите оператора проверить конфигурацию runtime по [руководству по устранению проблем](../../TROUBLESHOOTING.md). |
| Ждёт вас | Прогон, задача, проверка или вопрос ждёт человеческого решения. | Откройте связанный элемент и сделайте следующий шаг, который показывает UI. |
| `input_needed` | Прогон задал человеку вопрос. | Текущий runtime не может передать ответ, поэтому прогон завершается как `needs_operator`. Изучите его и запустите новый прогон. |
| `needs_operator` | Продукт получил исход, который не может безопасно разрешить сам. | Изучите прогон и задачу в инспекторе задачи. Не считайте работу успешной и не повторяйте её вслепую. |
| Приёмка отклонена | Нет актуальной одобренной независимой проверки или задача изменилась после проверки. | Отправьте текущую версию задачи на независимую проверку и принимайте её только после одобрения. |

Ошибка действия появляется рядом с его формой. При неизвестном исходе
используйте предложенный повтор: он сохраняет исходный запрос и его
идентичность. Потерянный ответ не повод отправлять второй независимый запрос.
После подтверждённого отказа можно исправить причину и начать новую попытку,
если интерфейс предлагает это действие.

Если истёк сам доступ к пространству, перезапустите локальный UI и используйте
новый одноразовый адрес. Расширенное восстановление выполняет оператор из
терминала — см. [руководство по устранению
проблем](../../TROUBLESHOOTING.md). Не вставляйте в баг-репорт вывод
провайдера, промпты, учётные данные или локальный URL входа.

## Границы текущей версии

Agent Commons — alpha-версия для macOS и Linux. Он работает с локальными
инструментами провайдеров; Windows пока не поддерживается. Runtime провайдера
экспериментальный и может потребовать решения оператора.
