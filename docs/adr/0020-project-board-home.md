# ADR 0020: Доска проекта как главный экран

- Дата: 9 сентября 2026
- Статус: принято владельцем (decision scope `ux/project-board-home`,
  заменяет `ux/work-home-screen` от 9 сентября); реализация в этом же срезе
- Автор: координатор (Claude Fable) по прямому указанию владельца
- Входы: восстановленный исходный PRD
  `docs/archive/2026-08-09-original-visual-orchestrator-prd.md`, синтез совета
  `docs/archive/2026-08-09-original-visual-orchestrator-plan.md`, ADR 0009
  (роли и связи как сущности), ADR 0014 (task-first), решение владельца от
  19 августа о React Flow (`decision.33ZP85QCM4G48YWT79VFQM9E62`)

## Контекст

Исходный замысел продукта (9 августа): «Miro/Figma для проектирования
AI-организации» — бесконечный canvas как главный экран, агенты как узлы,
команды/отделы как контейнеры, связи двух типов, параллельная работа отделов,
трекер задач отдельной поверхностью. Эта модель была реализована в старой панели
(доска ролей с портами связей, проекция `ui/graph.py` с рангами подчинения),
затем последовательно выведена из продукта: pivot 19 августа объявил canvas
«вне пивота», PRD был переписан на месте 31 августа, ADR 0014 сделал Work
task-first и отклонил сущность Team «в этом срезе», решение 9 сентября
закрепило домашний экран «Сейчас» по задачам. В React-приложении дерева агентов
нет; вкладка Agents — плоский список и форма найма.

Владелец 9 сентября вернулся к исходной модели и потребовал: один проект = одна
бесконечная доска на главном экране; на доске можно создавать агентов, связывать
их, запускать несколько blueprint-ов (отделов) параллельно; трекер задач — отдельная
вкладка; результаты и задачи открываются от конкретного агента.

## Решение

1. **Доска — домашний экран проекта.** Навигация: Доска · Задачи · Библиотека ·
   Настройки. Вкладка Agents упраздняется: её содержимое (найм роли) переезжает в
   боковую панель доски. Старый `view=team` перенаправляется на доску.
2. **Узлы — постоянные роли** (`agent`, не template): имя, специализация,
   провайдер/модель, состояние текущего запуска (из tracker snapshot),
   счётчик задач и признак «ждёт человека». Действия карточки: Разговор,
   Результаты (scope agent), Задачи (переход в трекер с фильтром по агенту),
   Дать задачу (существующий Prepare run с предвыбранной ролью).
3. **Рёбра — записи `agent_link`** (проекция `/api/graph`: `link_from`/`link_to`,
   а также `reports_to` из `created_by_agent_id`). Перетаскивание порта с одной
   карточки на другую открывает связь существующим `POST /api/agent-links`;
   стрелка без записи в ledger не рисуется (позиция совета от 16 августа
   сохраняется).
4. **Отделы — рамки доски.** Рамка группирует роли; применение blueprint с доски
   создаёт рамку с ролями и задачами этого применения; роли можно перетаскивать
   между рамками. Рамки и позиции узлов — **операционное состояние доски**
   (per-project JSON под state root, приватные маршруты `GET/PUT /api/board`),
   не canonical truth и не ledger. Когда появится каноническая provenance
   применений (WP-11), рамки получат ссылку на application id; до этого рамка —
   расстановка пользователя.
5. **Параллельные отделы.** На одной доске может быть сколько угодно отделов, в
   каждом — свои роли и задачи; запуски из разных отделов ставятся в очередь
   брокера. Одновременная запись двумя исполнителями в один checkout по-прежнему
   запрещена (THREAT_MODEL, «один пишущий worker на checkout»); истинный
   параллелизм записи требует worktree-per-agent и отдельного ADR. Доска честно
   показывает состояние «в очереди» вместо иллюзии одновременности.
6. **Трекер задач** остаётся отдельной вкладкой «Задачи» со всем, что сделано в
   волне 1; получает фильтр по агенту (`?agent=agent.…`) для перехода с карточки.
   Представления «Сейчас/Карта/Все задачи» (прежнее решение) живут внутри
   вкладки задач, а не на домашнем экране.
7. **Технология:** `@xyflow/react` 12 + `@dagrejs/dagre` для автораскладки
   (решение владельца от 19 августа). CSS React Flow подключается файлом
   (CSP `style-src 'self'`); собственных inline-стилей нет.

## Инварианты

- Ничего на доске не продвигает canonical lifecycle на клиенте: найм, связь,
  запуск — существующие серверные операции с идемпотентными ключами.
- Раскладка доски не влияет на ledger и не читается как факт; потеря файла
  раскладки = автораскладка заново.
- Зелёный — только принятая работа. Состояния запусков и связей — текст + иконка.
- Обе локали; canonical-значения не переводятся.

## Альтернативы

- Оставить «Сейчас» домашним, доску сделать второй вкладкой — отклонено
  владельцем: доска и есть точка входа в проект.
- Хранить позиции в ledger — отклонено (совет 16 августа, ADR 0009):
  координаты не являются фактом организации.
- Считать отдел канонической сущностью Team сейчас — отложено до WP-11/ADR
  об objective/application provenance; рамка доски покрывает потребность без
  новой доменной семантики.

## Последствия

- Волна 2 плана `docs/plans/2026-09-09-ux-closure-tech-plan.md` перестраивается:
  сначала доска (этот ADR), затем WP-11 (provenance) как основа отделов, затем
  остальные пакеты. WP-09 («Сейчас» как домашний) переносится внутрь вкладки задач.
- Появляется новая приватная операционная поверхность `/api/board`
  (перечислена в `PRIVATE_COLLABORATION_ROUTES`), с ограниченной схемой и
  атомарной записью под state root.
- Старая панель остаётся доступной через Settings до тех пор, пока доска не
  покроет её функции (runtime-узлы за переключателем и т. п.).
