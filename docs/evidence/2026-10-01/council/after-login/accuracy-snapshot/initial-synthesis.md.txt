критик A–E. Синтез контроллера проверен по коду и результатам. Это не приёмка проекта.

[План исполнения](../../../../plans/2026-10-01-gpt6-and-product-completion.md)
владеет очередностью реализации. Этот документ сохраняет решения контроллера,
разногласия, границы исследования и доказательства продолжения.

## Независимость и восстановление

B/C/D получили тот же неподвижный исходный код, brief, инвентарь задач и памяти,
что A/E. Они не видели чужих ответов или последующей реализации. Исходный HEAD
`aa9d3733decb9bff2f1b24892167842334bcf6a5` дополнен исходным WIP; manifest SHA
`86481622e733a85b87a9e0f514eadf6497583dd6b6231a9f45fd9952a396eaa8`.
Это аудит общей исходной границы, а не доказательство прочтения каждым
участником всех строк всех 1324 файлов. Ограничения чтения сохранены в ответах.

Для общей критики всем пяти даны полные ответы A–E, один rubric, одинаковый
[фактический пакет](common-facts.json) после интеграции и профиль WP-20. Ответы
помечены буквами; только идентифицирующие заголовки A/D/E скрыты в отдельной
копии. Рекомендации моделей внутри текста не удалялись. Оригиналы сохранены
полностью, mapping раскрыт выше. Полной слепоты это не гарантирует. Новые
native-критики A/E запущены с пустой историей; никто не получил синтез или
чужие критики. Ранжирование и голосование не использовались.

Контрольные хеши — [manifest общего входа](critique-input-manifest.json),
единая задача критика — [rubric](critique-rubric.md). Файлы provenance:
[Claude first](execution-provenance.json), [Claude critique](critique-all5-execution-provenance.json),
[Grok first](first-C-provenance.json), [Grok critique](critique-C-all5-provenance.json),
[native A](critique-A-all5-provenance.json), [native E](critique-E-all5-provenance.json).
Новое наблюдение пяти текущих ролей в [инвентаре моделей](agent-model-inventory.json)
снято позже и не давалось критикам. В замороженном common-facts осталась старая
строка «Claude first replies still running»; её опровергают уже завершённые
первые ответы B/D. Входной пакет после запуска не переписывался.

Первые попытки B/D общей критики оборвались вместе с процессом-координатором,
не оставив финальных ответов. После проверки отсутствия процессов повторены
только эти две линии с теми же входами. Частичный расход неизвестен; обрывки
не посчитаны дополнительными мнениями. Процесс Grok пережил потерю supervisor,
дал полный видимый финал с `end_turn` в исходной попытке. OS exit code неизвестен;
его не подменяет статус провайдера. Тайм-аут ограничен 1200 сек на попытку.
Скрытые рассуждения, credentials и полные служебные логи не опубликованы.

## Выводы контроллера по доказательствам

1. **Первый GPT-6 профиль — Astra на CLI 0.159.3.** Основание — успешные точные
   builder/reviewer canaries, а не рейтинг моделей. Sol дал один terminal
   mismatch и один успешный повтор; обе попытки сохраняются. Роли остальных
   моделей остаются гипотезами до project eval. Транспорт проекта уже CLI,
   поэтому переписывать его на Responses API не требуется. Параметр reasoning
   effort в runtime-профиле пока не поддерживается.
2. **Эффективная модель важнее пина YAML.** Код подтверждает override через
   `extensions.model`. У пяти нынешних ролей он отсутствует. Две роли наследуют
   Codex builder, reviewer использует Claude. Один qualification JSON на профиль
   вытесняется при проверке другой модели; fingerprint включает модель и
   сохраняет защиту. Для одиночного пилота — последовательно квалифицировать
   точную следующую комбинацию; для конкурентной работы — отдельное изменение
   хранения receipts. Нельзя просто отключить эту проверку.
3. **Галерея уже улучшена в проверенных границах.** Имя/аватар всегда открывают
   агентскую выборку; появились миниатюры, фильтры, provenance и переход в задачу.
   Текущая проверка задачи подписана именно так. Эти изменения не надо повторять
   по старым ответам. `/gallery` имеет другой DTO: один клиентский filter не
   добавит отсутствующую серверную привязку автора.
4. **Следующий результат должен сохранять файлы.** Metadata-only публикация
   и TTL объявления preview не гарантируют архив изображений или работающий
   frontend после завершения прогона. Начинать можно с versioned image paths и
   ограниченного статического build, без универсального файлового MCP или
   менеджера произвольных приложений. Missing bytes остаются unavailable.
   Review привязывается к точному manifest/content, а не наследуется из новой
   версии задачи. Это открытые G5/G7, а не повод заново делать интерфейс G3.
5. **Карта зависимостей и декомпозиция — разные функции.** Поиск, fit/zoom,
   upstream/downstream/connected focus до лимита 128 и нейтральный completed уже
   реализованы. Для project→component→task нужны явные parent/component данные,
   отдельные правила изменения, циклов и ревизий. Objective/application полезны
   для группировки, но не подменяют каноническую декомпозицию G6. React Flow против
   SVG остаётся инженерным выбором, не приёмочным критерием.
6. **WP-20 не достиг цели.** Диагностические медианы 13,2–18,6 сек относятся к
   3206 событиям; 2,26 сек из прежнего малого fixture нельзя сравнивать с 33 сек
   большого. Дополнительный cProfile выявил второй полный проход после своего
   append: 3206+3207 чтений. [Диагноз](wp20-performance-diagnosis.md) предлагает
   узкий эксперимент, не готовый патч и не обещание ≤1 сек. Дефекты корректности
   legacy recovery и resolved path уже исправлены и проверены отдельно.
7. **Старые задачи и опыт сверяются адресно.** Completed не означает accepted;
   возраст ready-задачи не доказывает supersession. Linux L1/R2 нельзя отменить
   как «старый хвост». Findings/decisions/handoffs сохраняют опыт, но каждый
   актуальный blocker требует привязки к нынешнему коду. Название UI-пакета и
   согласие пяти моделей не дают права автоматической приёмки.
8. **Техническая аудитория получает проверяемые детали.** Приоритетны
   агент↔задача↔результат, точный diff/build/tests, версия и автор, эффективная
   модель, причина отказа и восстановление, клавиатура и deep links. Проценты,
   стоимость и сроки не выводятся из недоказанных предположений. WP-42/C6
   продолжаются по своим критериям, но не блокируют каждый полезный UI-инкремент.

## Существенные разногласия и исправления критики

B/D предлагают больший предварительный объём: общий файловый MCP, React Flow,
визуальный фундамент и удаление legacy. A/C/E предпочитают существующую
агентскую панель и ограниченный путь до реального результата. Выбран второй
порядок; это решение контроллера по коду и выполненным проверкам, не «победа»
авторов. Общий файловый вывод полезен для документов и diff, но отдельным пакетом.

Критики тоже содержат ошибки. Успешный диагностический Sol canary существует;
его нельзя пропускать, равно как нельзя им стирать первый отказ. Первые ответы
не могли знать позднейший профиль WP-20. Строка о ещё работающем Claude в общем
дополнении устарела. Предложение `--reasoning high` не подтверждено CLI; отдельные
ограничения API из официальной документации не создают такого поля в профиле.
Публикация live URL не доказывает ни неизбежную смерть, ни жизнь сервера после
прогона. Повторять Sol до удобного результата нельзя: нужен заранее ограниченный eval
с сохранением всех неуспехов. Доступность diagnostics и reopen надо проверять по фактическому DTO/UI,
а не принимать отрицательные утверждения из старого отчёта.

## Реализация и незакрытая граница

Прежний `make check`: 2738 Python passed, 14 skipped; 401 Work и 27 Gallery.
[Независимое review](../final-review.md) одобрило только точный UI/storage
инкремент. Эти проверки не повторялись ради новых текстов и не стали проверкой
всего релиза. После продолжения выполнена проверка документационных ссылок.

Настоящий bounded Astra frontend-run выполняется отдельно. Пока его результат
не проверен, успешные canaries и браузерные fixtures не объявляются продуктовым
доказательством. Операторские профили не переключены. Долговечные builds,
проверка конкретного результата, каноническая декомпозиция, WP-20 performance,
authenticated Linux и release evidence остаются открытыми. План содержит
критерии каждого пакета и сохраняет эти ограничения.
