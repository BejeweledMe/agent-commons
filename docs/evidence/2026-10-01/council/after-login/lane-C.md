## Фактическая архитектура

Agent Commons — локальное приложение: неизменяемый файловый леджер, проекции, брокер запускает подписочные CLI. Продукт описан в `docs/PRODUCT.md`: проект открывается на доске `/work`, трекер — `?view=work`, результаты — кнопка у задачи или агента, пакеты дизайна — отдельное приложение `/gallery`. Клиент не двигает жизненный цикл; зелёный только у приёмки (`docs/FRONTEND_CONTRACT.md`).

Запуск — не HTTP API. `CodexRunnerProfile.build_invocation` собирает `codex … exec` и при непустой модели добавляет `--model` (`src/agent_commons/runtime/model.py:814–845`). То же `--model` у Claude (`:979–980`) и Grok (`:1132–1133`). Имя модели — идентификатор `^[A-Za-z0-9][A-Za-z0-9_.:/-]{0,255}$` (`model.py:25`, `validate_model_name` `:434–451`); точка в `gpt-6.1-sol` этим шаблоном не запрещена. Поля reasoning effort, temperature, top_p в argv нет. Денежный бюджет Codex и Grok не умеют (`:797–798`, `:1087–1088`). ADR 0018 (подключение hosted API) — proposed, не реализация. `docs/ROADMAP.md:48–50` прямо откладывает API-провайдеров. Пин модели в профиле оператора и при найме — правильный шов. Миграция на Responses API для GPT-6 здесь не нужна и противоречит принятому local-first.

Доска (`frontend/work/src/components/ProjectBoard.tsx:31–48`) рисует имя, специализацию, профиль, модель, счётчик задач и четыре действия: разговор, «Результаты», задачи, «дать задачу». Клика по карточке или иконке нет. «Результаты» монтируются только если сервер уже отдал `total > 0` (`OutputsPanel.tsx:54–56`). Тест это закрепляет: `count` `null` и `0` дают пустую разметку (`frontend/work/tests/outputs.test.mjs:53`). Так и сказано в ADR 0019: кнопку результатов показывать, только когда есть доступные выходы. Пустое и ошибочное состояние диалога есть (`OutputsPanel.tsx:100`), но с доски до него не дойти.

Сервер уже режет выходы по производителю, не по текущему исполнителю задачи (`services/outputs.py:216–249`, `generated_outputs.py:21–39`: ровно один кандидат, иначе запись отбрасывается). Два вида: картинка (`design_image` / `artifact_image`) и live preview. Картинку публикует воркер `commons_publish_design_image` (`mcp/design_output_tools.py:44–57`), превью — `commons_publish_live_preview` (`mcp/live_preview_tools.py:45–58`). Превью — объявление origin `127.0.0.1`/`[::1]`; процесс никто не стартует, достижимость не проверяется. На проводе `reachability` всегда `"unknown"` (`ui/output_routes.py:115–134`). Ссылка в UI есть только пока объявление не протухло (`OutputsPanel.tsx:117–125`).

Происхождение на проводе есть и клиентом выбрасывается. `parseOutputList` проверяет `task_id`, ревизии, `producer_agent_id`, пакет и экран, затем кладёт в модель заголовка только заголовок, артефакт, хеш, состояние и `reviewState` (`outputsTypes.ts:67–97`). У live-объекта идентификаторы тоже проверяются и не сохраняются (`:103–120`). `review_state` картинки — вердикт задачи-производителя, не экрана (`outputs.py:437–469`): `approved` / `changes_requested` / `requested`, устаревший review не показывается. У live-записи этого поля нет. Отдельный `/gallery` — каталог пакетов, не галерея агента (`frontend/gallery/src/main.tsx`). Старые ссылки Design уводятся в трекер (`appRouteState.ts:40–41`).

«Карта» — третья вкладка трекера, по умолчанию открыта «Сейчас» (`appRouteState.ts:4–6`, `TaskViews.tsx:98–107`). Раскладка самописная, не React Flow доски: ранг зависимости, затем перенос по 4 узла (`taskGraph.ts:81–86`), потолок 128, цикл или битое ребро дают список вместо графа (`TaskGraph.tsx:21–22`). Клик выбирает задачу. `objectiveId` и `applicationId` на `TrackerTask` есть (`contracts.ts:407–415`) и в раскладку не входят; цель видна сырым id в карточке решения. Рёбра для скринридера скрыты (`aria-hidden`, `TaskGraph.tsx:28`). Иконки — символы `✓ ▶ !`, не граф компонентов.

Запись на большом фикстурном леджере измерялась 10 сентября: warm `task_create` медиана 33,25 с при 3206 событиях, из них ~21 с — повторное чтение канонических файлов (`docs/performance/2026-09-10-mutation-baseline.md:57, 77`). ADR 0023 — черновик, не в силе. В `manager.py` уже есть `_VerifiedLedgerView` (вариант «проверить байты, не перевалидировать»). Это не доказательство цели D-16 (≤1 с). Вариант B по квитанциям я на горячем пути не прослеживал. `doctor` этот снимок я не гонял.

Координатор сообщил: 4212 событий, 418 manifest, `doctor ok=true`, 173 предупреждения; задачи 304 = 173 accepted, 52 completed, 69 cancelled, 9 ready, 1 review. Я `TASKS.json` по состояниям не раскладывал (файл — одна гигантская строка) и `decisions.json` целиком не читал. Числа координатора не перепроверены.

Нет и не надо изобретать: процента прогресса, графа файлов как канонической декомпозиции, Linear, API-адаптера GPT-6.

Планы 18 и 21 сентября — не код. Из них в дереве видно: WP-40 в `mcp/scoped_repo.py:106–132` (не-файл и вложенный worktree пропускаются через `lstat`, без перехода по symlink); StopReason в UI; in-memory verified view. ## Опыт, который не повторять

- Аддитивное поле сервера ломает клиент с точным набором ключей. Так упала доступность провайдеров после `wall_time_seconds` (finding `017DAFGE…`). Любое новое поле выхода — в том же изменении, что и `keys()` в `outputsTypes.ts`.
- Grok трижды выходил 0 без `commons_report_outcome` (WP-08, WP-16.2, WP-15.3). Не назначать ему закрытие канонического исхода, пока это не исправлено отдельной проверкой.
- Вывод провайдера не истина. В Blizhe (`docs/handoffs/2026-09-21-blizhe-dogfooding-feedback.md`) процесс `succeeded` соседствовал с `needs_operator` и непривязанными файлами. Общий `register_artifact` воркеру по-прежнему не найден; есть только публикация картинки и превью. Markdown-результат сам в галерею не попадёт.
- Смена установленного bundle инвалидирует canary при `qualified:true` в старых receipts. UI называл это ошибкой проверочного запуска (UX-29). Новый пин модели без текста «отпечаток профиля устарел» повторит этот тупик.
- Не принимать пачкой старые review и не лечить 173 предупреждения `doctor` как дефект галереи. План C7 уже зафиксировал: stale review — факт о старой ревизии.
- Не полировать шрифт до того, как карточка показывает результат. Это уже решённый порядок D-23, и он всё ещё верный.
- Не выводить владельца из имени специализации. Пустая галерея дизайнера и пустое превью фронтенда — независимые секции одних и тех же данных.

## Блокеры

**P0**

1. Нет входа. Карточка не кликабельна; кнопка результатов исчезнет при нуле. Прямой конфликт с запросом и с ADR 0019 / `outputs.test.mjs:53`.
2. Происхождение выбрасывается после проверки. Показать его можно без нового серверного поля для картинок; для live review поля на проводе нет.
3. «Рабочий frontend» в данных — непроверенное объявление. Написать «превью работает» нельзя.
4. Карта врёт пространством: ранг шире 4 узлов заворачивается, цель не группирует, зависимости немой svg. Это не отсутствие данных.
5. Запись ~33 с на 3206 событиях делает цикл vibe-coding непригодным на этом леджере. Для открытия галереи не блокер, для повседневной работы — да. ADR 0023 не принят, повторного замера после `_VerifiedLedgerView` в снимке нет.
6. Пин GPT-6 без canary на том же CLI и без честной инвалидации квалификации повторит UX-29. Строка модели CLI в репозитории не зафиксирована; официальные имена API (`Astra`, `6.1 Sol`, `Luna`) нельзя подставлять в `--model` наугад.

**P1**

- Review один на задачу, не на версию экрана. Честно, но грубо. Новый тип «review экрана» не делать в первом шаге.
- Legacy-панель ещё обслуживается (C6). Путает, куда писать фичу. Новые поведения только в Work.
- Строки «роль» (WP-30). Не путать с блокером галереи.

- Привязка проекта по `device:inode` ломает панель после смены номера устройства (finding `3CSE9Y5…`). Операционный, не продуктовый.

## UX для сильного разработчика

Не три колонки вместо графа и не прятать ULID. Спрятанное — в disclosure, в один жест, с копированием.

**Галерея агента.** Клик по имени карточки (класс `nodrag`, чтобы не начинать перетаскивание React Flow) всегда открывает существующий диалог `OutputsPanel` со scope `{kind:"agent", id}`. Кнопка «Результаты (N)» остаётся как сейчас: её нет, пока сервер не дал положительный счёт. Так не ломается тест на `OutputsAction` и правило «кнопка только при известном счётчике».

Две секции, обе всегда на экране:

- Макеты: `design_image` и `artifact_image`. Пусто: «этот агент не опубликовал ни одного кадра». Не «у дизайнера нет макетов».
- Превью: `live_preview`. Пусто: «объявлений превью нет». Состояния, которые уже есть, сохраняются: загрузка, ошибка списка, ошибка байтов картинки, stale, unavailable, unchecked, historical, expired, starting. У превью первая строка reachability — «не проверялось», код `unknown`. Ссылка только при `reported_ready` и живом TTL. Отдельный origin, без cookie Commons.

Первая строка кадра: заголовок, подпись latest/previous, чип review только если сервер прислал `review_state` (у картинок уже так). Идентификатор задачи — тот, что парсер уже проверил; заголовок задачи подставляется из открытого снимка трекера, если задача там есть, иначе остаётся id. Disclosure: `task_revision`, `content_revision`, `producer_delegation_id`, `package_id`/`screen_id` для пакета, `reason`. История — уже существующий переключатель latest/all. Зелёный по-прежнему не для `approved` и не для `ready`. Специализация не выбирает секцию и не скрывает чужой вид: у фронтенд-инженера макеты тоже видны, если он их опубликовал, и наоборот.

`/gallery` из карточки не открывать: там нет фильтра по агенту, зато есть авторский контур пакетов. Смешивать их — второй продукт.

**Граф.** Оставить вкладку «Карта» и данные `TrackerEdge`. Один ранг — один ряд, горизонтальная прокрутка, без `% 4`. Группы — полосы по `objectiveId`, если null — по `applicationId`, иначе полоса «без цели». Узел: состояние из `graphTaskState`, заголовок, агент, число `blockingDependencyIds`. Клик — текущий инспектор. Вторая ссылка узла — результаты этой задачи (тот же диалог, scope task). Счётчики по состояниям, не процент. Цикл, отсутствующая предпосылка и >128 остаются явной деградацией в список; это целостность, не «упрощение». Компонент кода из дерева файлов не строить: в леджере нет такой сущности, а агент и цель уже есть. React Flow на карту в этом шаге не переносить: доска им уже пользуется, но чужой layout не чинит отсутствующую группировку и тащит риск inline-style против CSP.

## Риски и несогласие

Клик по узлу React Flow легко превращается в drag; без `nodrag` на имени инкремент будет «иногда открывается». Точный парсер ключей снова уронит весь список, если review у live добавить обязательным полем — только optional и `null` = нет подписи. Превью можно принять за запущенный сервер; текст должен это запрещать. Группировка по цели не заменяет отсутствующий заголовок цели: id в полосе честнее выдуманного имени.

Не согласен с рекомендацией консилиума 21 сентября пересаживать карту на React Flow в первую очередь: дефект — раскладка и игнор `objectiveId`, библиотека уже не поможет быстрее, чем правка `buildTaskGraph`. Не согласен прятать пустую галерею ради ADR 0019: кнопка счётчика пусть остаётся, вход с имени — нет. Не согласен строить «компоненты» из исходников. Не согласен вести GPT-6 через Responses: в коде нет этого транспорта, а запрет temperature без reasoning none на CLI-пути и так соблюдён, потому что эти параметры не отправляются. Визуальный фундамент WP-42 после G1, не вместо него.

Не проверено этим проходом: `make check`, `doctor`, браузер, полный разбор 304 задач и всех findings, diff незакоммиченного дерева против `aa9d373`, фактический slug модели в установленном Codex, горячий путь квитанций после ADR 0023, живой прогон публикации картинки. Согласие следующей стадии это не заменит.
