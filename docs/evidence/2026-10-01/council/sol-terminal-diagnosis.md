# Sol 0.159.3: ограниченная диагностика terminal-исхода

1 октября 2026. Точная модель `gpt-6.1-sol`, Codex CLI `0.159.3`, Agent Commons source SHA `fab6f03a9ca61162e4495cc8758c662cf4720a7588d7cbee169b8e2c4dcc274e`. Операторские настройки, auth/billing, исходники и основной ledger не менялись. Все пять model attempts были отдельно разрешены координатором; этот последний — единственный дополнительный запуск для диагностики прежнего ValidationError.

Последний запуск успешен: synthetic preflight/initialization зелёные, process exit 0, canonical `succeeded`, terminal calls/completions/rejections `1/1/0`, mismatch false, child session closed. Длительность 54.73 секунды. Sol вызвал `commons_succeed_delegation` с существующей typed task reference. Безопасное итоговое сообщение: «Delegation success recorded. Scoped inspection confirmed `[path]` defines `answer()` returning integer `42`. No changes were needed.» Terminal summary также отмечает недоступность CLI startup-команд и подтверждение session/target через инжектированные Commons tools. Следовательно, недоступность CLI startup не делает успех через MCP невозможным.

Первый Sol canary на той же версии завершился иначе: exit 0, canonical `needs_operator`, terminal `2/1/1`; первая `commons_delegation_needs_operator` отклонена с ValidationError. Сервис сохранил только `details withheld: the refusal text may quote tool arguments`. Исходные arguments/result/final summary первого запуска не сохранялись; temporary fixture уничтожена. Новый диагностический запуск прежний отказ не воспроизвёл. Поэтому **точную категорию invalid argument и мотив прежнего выбора needs_operator установить нельзя**. Называть причиной невалидный reason_code, stale revision либо отсутствие complete_task было бы догадкой. Возврат generic ValidationError сам по себе не различает поля.

Проверены все семь условий окружения: ambient STATE_ROOT, STATE_BASE, SESSION_ID отсутствуют; actual child STATE_ROOT равен переданному broker synthetic root и расположен в temporary fixture; SESSION_ID и DELEGATION_ID равны назначенным broker identity. Неправильный унаследованный main state не проник в последний child. Прежние новые-CLI запуски также запускались с явным env -u этих трёх переменных. Для первого из них дополнительных child-environment доказательств не собиралось, поэтому итоговая трассировка окружения относится именно к диагностическому запуску.

Код объясняет потенциальную неоднозначность, но не доказывает причинность прежнего отказа. Synthetic source уже удовлетворяет acceptance: services/provider_canary.py:169,277; implementation fixture остаётся active, complete_task выполняется только для других purposes (:287–299). Делегированная инструкция требует «normal task/artifact/review workflow» и «honest completed result» (services/delegation_instruction.py:151–162). При этом implementation успешный terminal принимает существующий task ref (mcp/server.py:1440–1473), а worker catalog не предлагает complete_task (mcp/server.py:149–180). Последний Sol правильно счёл точную проверку готового source достаточной. Это область для отдельного review ясности canary/инструкции; она не служит основанием переписывать prompt или повторять paid attempts ради зелёного результата. Reason_code enum действительно ограничен (resources/schemas/domain/delegation.v1.schema.json:93–107), но отсутствие исходных аргументов не позволяет связать этот enum с прежним ValidationError.

Данные сохранены в `canary-sol-cli01593-terminal-diagnostic.json`: только общий canary report, безопасные terminal invocation/result bodies, последний user-facing summary и булевы доказательства окружения. Entity IDs и пути заменены маркерами; reasoning, обычные tool calls, prompts и полный transcript не сохранялись. Qualification receipt не записывался.

Рекомендация: старый CLI 0.145.0 явно блокирует эти модели; изолированный 0.159.3 снял старые HTTP400. Astra на 0.159.3 имеет один чистый успешный exact-model review canary. Sol на 0.159.3 теперь имеет один отрицательный и один положительный builder canary; это подтверждает доступ и возможность MCP-terminal успеха, но не стабильность поведения. Для перехода на Sol сохранять оба результата и отдельно решить квалификацию по действующему release gate; не выдавать последнее зелёное наблюдение за опровержение первого mismatch. Дополнительные model retries не выполнялись.
