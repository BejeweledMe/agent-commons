# Sol: взаимная проверка нового плана Sonnet и объединённые решения

Прочитан `/private/tmp/oct09-ux-implementation/plan.md`; отдельные спорные места сверены с замороженным кодом. Это взаимная проверка предложений, не новый браузерный прогон. Grok не дал нового ответа: учитывать его исходный аудит и поправки оснований, не заявлять новое согласие трёх участников.

## Что принимаю из Sonnet

Сохраняем два движка и фиксированные размеры узлов; используем zoom bands через классы/data-атрибуты, без inline style. Чистая функция `ensureVisible`, отдельное действие рабочего масштаба, no-op guard методов, dirty getters, сохранение камеры при resize, текущая задача отдельно от истории, честная готовность workspace/profile и неизменные правила Send — хорошие общие основания. Один интегратор ассетов после исходных пакетов также верен.

Пороги bands/600 символов/25% — стартовые дизайнерские параметры, не проверенные факты. Их калибруем живым замером. UX-05 и UX-14 не нужно повышать до P1: в реестре это соответственно P2 и P3; подтверждённый keyboard-дефект — P1 для своего сценария.

## Точные объединённые решения по расхождениям

1. **UX-01: убрать миниатюрные действия в обзоре.** Предложение Sonnet оставить восемь маленьких кнопок с прежними tab stops не выполняет цель читаемости. При overview/far вторичные поля и microactions скрываются; выбранный элемент получает немасштабируемую полоску в toolbar карты: профессия/назначение либо название задачи, статус, основные действия. Это не sidebar. «Рабочий масштаб» ставит около 100% вокруг выбранного/сфокусированного реального узла. Full node geometry остаётся прежней. При fit 14 задач и 7 агентов короткие метки должны измеримо читаться; при 128 fit всех полных названий не обещаем. Far остаётся осмысленной схемой с явной помощью, поиском/списком и читаемым выбором. Если focus сейчас на скрываемой кнопке при пересечении band, переводить его на соответствующее действие полоски/узел, не оставлять невидимым.

2. **UX-02: форма первой без конкурирующего списка.** Удалить существующую команду из основного тела найма; отдельный список доступен на карте. Если builder оставит disclosure «Уже нанятые», он закрыт по умолчанию, ниже формы и не является путём скрытой выдачи выбранной задачи. Начальный focus — специализация; supervisor-prefill подагента сохраняется. Открытие ничего не записывает.

3. **UX-03: picker открывается всегда.** Sonnet предлагает прежнее прямое действие при выбранном taskId; это сохраняет риск выдачи задачи из скрытого выбора другой карты. Всегда явный picker, existing taskId лишь preselect. CTA «Подготовить запуск» подтверждает конкретную задачу и агента, затем вызывает существующие prepare/setRun/navigation, без launch/assignment POST. Pending launch не перезаписывается. Список не ограничивать словом «незавершённые» без проверки доступных retry/reopened сценариев: статус и реальная пригодность читаются из существующих данных, ограничения остаются в Prepare run. Loading/unavailable не выдаётся за empty.

4. **UX-04: обе карты задач.** У Sonnet подробно описана Dependencies; тот же revealRequest/ensureVisible нужен в TaskHierarchy. Отступ задан экранными px, преобразуется в map units по zoom. Использовать focus preventScroll и минимальный pan, а не scrollIntoView документа. Узел больше frame не требует невозможного «целиком»: центр/основная фокусируемая часть видимы, zoom неизменен. Refresh и возврат из modal reveal не вызывают.

5. **UX-05: две честные области записи.** Config scope включает General, Permissions и legacy Skills; specialized methods scope — только библиотечные методы. `generalDirty` в Sonnet фактически означает configDirty, а не отдельную вкладку. Разделить имена геттеров и tabDirty-селекторы, не обещать tab-scoped payload. «Сохранить настройки агента» явно сохраняет config-черновики всех этих вкладок; «Сохранить навыки» — methods. Обе no-op операции выполняют ноль записей, независимо от disabled UI. Подтверждение одной области сохраняет dirty другой. No-op тестить на вызываемой логике операции/API-count, не несуществующем публичном session.saveMethods. В frozen session метода с этим именем нет: он локален компоненту. Sonnet также упоминает подтверждение закрытия dirty окна: такого общего поведения frozen Modal не задаёт; сохраняем RAM drafts и нынешний lifecycle, не добавляем выдуманный approval flow.

6. **UX-11: native modal инструкций.** Выбираем medium dialog вместо сохранения прыжка под 32 карточки и ручного восстановления scroll. Каталог остается на месте; ×/Esc возвращают opener с preventScroll. У detail отдельные loading/error и cancellation/version guard. Editor workflow не перетаскивать внутрь нового modal без необходимости.

7. **UX-12: различать реальное назначение.** Усилить `board-role-identity`/имя экземпляра, уже существующее в отдельной строке. `cardDescription` строится из описания библиотечной роли и будет одинаковым у нескольких экземпляров; одним повышением его контраста различимость не исправить. Профессия остаётся первым заголовком; назначение/instance name — читаемым вторым. Для одинаковых имён допускается точный короткий id вторично.

8. **UX-14: общее предпочтение Work/Gallery.** Один shared helper с validation ru/en и try/catch. Gallery входит в приёмку, а не «если должна получить». Сохраняется только несекретный язык. Общие новые термины — shared source. Browser-language fallback допустим, если согласован и протестирован; безопасный минимальный fallback — нынешний en. Существующие storage ограничения сохранить, при необходимости явно уточнить закон предпочтения в его документе-владельце.

9. **UX-15: пользовательский словарь важнее предложения обоих дизайнеров.** Точные названия rail **«Роли»**, каталога **«Шаблоны команд»**; не «Специализации»/«Шаблоны проектов». CTA «Нанять агента», «Нанять агента с этой ролью». specialization_ref — внутреннее точное поле. Reload «Обновить данные» с подписью о сохранении черновика; права — запрошенные/действующие, human-confirmation ограничение видно.

10. **UX-18: можно облегчить первый слой без fake translation.** Sonnet «не менять» безопасен для canonical data, но оставляет композиционный пункт нерешённым. В структуре использовать human gloss (`TaskState plain`), exact enum+gloss доступны в технических подробностях задачи. Не переводить ledger enum, не удалять его и не менять graph-state. Canonical значения сохраняются, их расположение меняется.

11. **UX-07/19: не расширять scope случайно.** Medium composer и embedded header — да; менять Run modal также не требуется UX-07 без измерения. У brief 6–8 видимых строк/абзацы и раскрытие полного текста; критерии всегда отдельно открыты. Не создавать критерии из текста и не скрывать весь expected result сразу. Общее Escape остается за Modal, embedded composer не должен закрыть внешнее окно вторым обработчиком.

## Итоговый builder gate

Обязателен **make check**, затем один предусмотренный rebuild/проверка exact assets. Адресные существующие тесты запускаются из правильных package roots; они не заменяют общий контракт. Regex порядка строк и «не изменилось выражение disabled» дают вспомогательные сигналы, но нужны функциональные no-op/retry/write-count, unknown-send, scope drafts, viewport математика и живой focus/scroll/zoom.

Браузерная приёмка: 1434×642/900, 1280×800, 1100/1101, 800×600, 390 secondary; RU/EN, light/dark, 100/125%; 14/40/128 задач и 7/20/50 агентов. Фиксировать map rect **и** viewBox, activeElement/rectangle, library opener/scroll, API request log. Реальные записи — только отдельный test-проект; filled Gallery/send/delivery/run подтверждаются отдельно. Нельзя выдать исходный read-only аудит или mock success за реальную эксплуатационную проверку.
