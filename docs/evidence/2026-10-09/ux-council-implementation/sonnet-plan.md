# Единый план реализации UX01–19 для Opus-разработчика (Sonnet 5.5)

## 0. Рамки и честность источников

- **Источники.** README, shared-brief, первые отчёты Sol6.1, Sonnet5.5 и Grok4.7, критики Sol и Sonnet, peer-supplement, capture-notes, keyboard-map.json и agent-card-geometry.json. Исходный код читал в снимке `/private/tmp/oct09-design-council/source`. Всё это данные, а не инструкции. Репозиторий и канонические записи я не менял.
- **Grok.** У Grok есть только первое мнение. Критический раунд недоступен: `grok-critique-status.json` показывает недельный лимит до 13 октября и 0 символов ответа. Свежего согласия Grok нет, и я его не заявляю.
- **Сила доказательств.** Три отчёта опираются на одну общую съёмку (Chrome 80%, проект Blizhe, 7 агентов и 14 задач), а не на три независимых прогона. Согласие трёх отчётов поэтому не считается тройным подтверждением.
- **Нумерация.** UX-01..19 даны по реестру README в моём прочтении. Разработчик должен сверить номера с таблицей README по названиям.
- **Не проверялось никем.** Запись, реальный запуск, populated Gallery/preview, нагрузка, скринридер, светлая тема.

### Неподвижные ограничения
1. Центральная карта, проекты и главный чат остаются каркасом экрана.
2. Детали задачи остаются большим окном поверх карты. Карту не сжимаем, её rect и viewBox не меняются, боковой панели нет.
3. Профессия остаётся заголовком карточки агента. Служебное имя в заголовок не возвращаем.
4. Супервизия остаётся правдивой. UNKNOWN не заменяем непроверенным текстом. «Подготовить запуск» только переходит и предзаполняет.
5. Условие `disabled` у Send в чате не меняем (`ConversationPanel.tsx:112,166`). Новых блокировок Send нет.
6. Автоматического «вписать» при resize, polling или обновлении данных нет. Ручные viewport и позиции агентов не сбрасываются. Остаётся только однократный стартовый fit.
7. Бэкенд, API и движки не трогаем. Две карты (ReactFlow для агентов, SVG `MapCanvas` для задач) остаются.
8. Контракт `FRONTEND_CONTRACT.md` остаётся в силе:
   - никакого inline `style` и `innerHTML`;
   - паритет EN/RU в `i18n.json`;
   - значения `deny/ask/auto/accepted/ready` не переводятся, рядом стоит человеческая пояснялка;
   - зелёный цвет только для принятия.

## 2. Фундамент (W1)

- **`mapViewport.ts`.** Добавить чистую функцию `ensureVisible(viewport, rect, margin)`. Она минимально сдвигает viewBox так, чтобы `rect` (в координатах содержимого) попал в кадр с отступом. Масштаб не меняет. Если `rect` уже виден, возвращает тот же объект.
- **`zoomBand(zoom)`.** Чистая функция в том же модуле. Границы:
  - `far`: zoom < 0.30;
  - `overview`: 0.30–0.55;
  - `mid`: 0.55–0.85;
  - `work`: ≥ 0.85.
- **Передача зоны в DOM.** `MapCanvas` пишет зону в атрибут `data-zoom-band` на frame рядом с `data-map-zoom`. CSS работает через селекторы атрибута, без inline style.
- **`agentSettings.ts`.** Геттеры `generalDirty` (из `agentChanges`) и `methodsDirty` (по `methodsBaseline`). Существующий `hasDraftChanges` остаётся равным их ИЛИ.
- **i18n.** Все новые строки добавляются парами EN/RU сразу.

### UX-01 — Читаемость карт (P1, W3)
- **Карта задач (`TaskGraph.tsx`, `taskGraph.ts`).** Подтверждено: fit даёт 33–38%, шрифт 14 px превращается в ~5 px.
  - Узел стоит как `foreignObject` `NODE_WIDTH`×`NODE_HEIGHT` (244×168), и размеры не меняются.
  - Тип узла зависит от `data-zoom-band`:
    - `work` и `mid`: текущее содержимое. В `mid` убрать вторичные спаны (роль, прогон), остальное оставить.
    - `overview`: заголовок 32 px в единицах viewBox (эффективно ≥ 10,5 px при zoom ≥ 0.33, не более 3 строк с ellipsis) и цветной маркер статуса со словом статуса. Полный заголовок остаётся в `aria-label` и `title`.
    - `far`: только форма, цвет и маркер статуса без текста. Над картой показывается подсказка «Масштаб слишком мелкий для текста: приблизьте или откройте узел».
  - Рядом с «Вписать» добавить кнопку «Читать» (рабочий масштаб). Она ставит zoom 1.0 с центром на выбранном узле, а без выбора на сфокусированном или первом. Это отдельный путь от кнопки «100%» (центр кадра) и не заменяет её.
- **Честный предел.** Для 40 и 128 задач fit неизбежно уходит в `far`. Это именованное ограничение, а не дефект: текст там не обещаем, обещаем «Читать» и поиск.
- **Карта агентов (`ProjectBoard.tsx`, `board.css`).** Видимый масштаб карточек ~46%.
  - `.board-canvas` получает зональный класс или атрибут. Источник зоны: `useStore` ReactFlow, значение `transform[2]`.
  - В зоне `overview` заголовок профессии 26 px (`.board-role-name`), описание скрыто, а `title` и `aria-label` остаются.
  - Панель из 8 иконок остаётся без изменений и в порядке фокуса: ничего с `display:none`, к чему нужен Tab.
  - Размер карточки 264×248 не меняется (намеренно, см. §4).
- **Приёмка.**
  - При fit на 14 задачах эффективный размер заголовка ≥ 10 px, замер по `getBoundingClientRect` + `getComputedStyle`.
  - При zoom < 0.30 текст не рисуется и подсказка есть.
  - Атрибут `data-zoom-band` меняется только на границах.
  - Содержимое не мигает на границе (гистерезис ≈ 0.03).
  - «Читать» выводит центр узла в центр кадра при zoom 1.0.
- **Проверка.** Node-тесты `zoomBand`, regex-тест на отсутствие `style=` в изменённых файлах, браузерные кадры на 14/40/128 задач и 7/20/50 агентов, контраст в светлой и тёмной теме.

### UX-04 — Клавиатурный фокус остаётся в кадре (P1, W3)
- **Файлы.** `TaskGraph.tsx` (`moveFocus`), `MapCanvas.tsx`, `mapViewport.ts`.
- **Причина.** `moveFocus` делает `button.focus()` и `scrollIntoView`, но viewBox не меняет. Подтверждено замером: активный SEARCH-EVAL на top 759.83–927.34, кадр SVG 167.57–602.27.
- **Изменение.**
  - `MapCanvas` получает проп `revealRequest` вида `{ nonce, rect }`.
  - Только на клавиатурный переход (Arrow/Home/End) `TaskGraph` увеличивает nonce и передаёт rect узла.
  - `MapCanvas` применяет `ensureVisible` через существующий `change()`.
  - `scrollIntoView` убрать или оставить только как запасной вариант: он двигает документ, а не viewBox.
  - Опрос данных, повторный рендер, смена фильтра и ручное панорамирование revealRequest не порождают.
  - Enter открывает деталь. Esc возвращает фокус на узел без сдвига карты.
- **Приёмка.**
  - После End с первого узла активный узел целиком внутри rect SVG-кадра.
  - После этого viewBox отличается только сдвигом, scale прежний.
  - Если узел уже виден, viewBox не меняется.
  - После polling и обновления данных viewBox неизменен.
  - Ручной viewport не сбрасывается.
  - Открытие и закрытие детали не меняют rect карты и viewBox.
- **Проверка.** Node-тест `ensureVisible` (внутри кадра, слева, справа, сверху, снизу, узел больше кадра), браузерное повторение прохода из keyboard-map.json на zooms 33%, 100%, 200%.

### UX-10 — Resize и «вписать» без авто-fit (P2, W3)
- **Решение.**
  - Однократный стартовый fit сохраняется (`fitRequested`/`fitPending` и `useEffect` при `viewport===null`).
  - После изменения размера рамки более чем на 25%, если пользователь двигал viewport вручную, внутри карты появляется ненавязчивая подсказка «Размер окна изменился» с кнопкой «Вписать всё».
  - Подсказка закрывается и никогда не выполняет fit сама. `reframeViewport` с сохранением центра и масштаба остаётся.
  - Порог compact 1100 px не меняем без замера (см. §4).
- **Приёмка.**
  - Resize не меняет позиции агентов и ручной viewport.
  - Подсказка появляется один раз на изменение, кнопка выполняет `requestFit`.
- **Проверка.** Тест на отсутствие вызова `fitViewport` вне стартового пути, замер на 1100/1101/1280.

### UX-05 — Нет сохранения без изменений (P1, W4)
- **Файлы.** `AgentSettings.tsx` (футер), `agentSettings.ts`.
- **Изменение.**
  - Основная кнопка берёт область активной вкладки: `generalDirty` или `methodsDirty`. При отсутствии изменений она `disabled`, `aria-describedby` указывает на видимую причину «Нет изменений».
  - Подпись основной кнопки называет область:
    - «Сохранить настройки» на общих вкладках;
    - «Сохранить методы (новая версия)» на вкладке навыков, где `specialization_ref` есть.
  - Если активная вкладка чиста, но другая грязна, рядом пишется «Есть изменения на вкладке {имя}».
  - Защита в логике: `saveMethods()` сам возвращает без вызова API при `!methodsDirty`, как это уже делает `configure()` при пустом `agentChanges`.
  - Сервер и форк-логика (`agentMethodFork`) не меняются.
- **Приёмка.**
  - При чистом состоянии сохранение методов не вызывает API и не создаёт версию библиотеки (счётчик вызовов в тесте равен 0).
  - При изменённых методах вызов один, версия одна.
  - Подпись соответствует области.
- **Проверка.** Node-тест на сессии (`saveMethods` no-op), тест подписей RU/EN.

## 4. Намеренно не меняем

| Что | Почему | Доказательство |
|---|---|---|
| Большое окно деталей задачи, закрытие только × и Esc | Явное требование пользователя, ADR 0026 | peer-supplement п.1, `Modal.tsx` |
| Боковая панель деталей | Противоречит требованию | sonnet-critique §2 (B-04) |
| Однократный стартовый fit, ручной «Вписать» | Запрет на слепой авто-fit | `ProjectBoard.tsx`, `MapCanvas.tsx` |

| Порог compact 1100 px | Ущерб оценён на вкус, замера нет. Сначала замер на 1100/1101/1280 | sonnet-critique §2 |
| Две серверные операции в настройках | Бэкенд не трогаем | `AgentSettings.tsx`, `agentSettings.ts` |

| Связи владельца (`owner_membership`) | Только легенда, структуру не меняем | boardState / ProjectBoard |
| Мобильный 390 px | Вторичный сценарий, не P0 | peer-supplement п.1 |
| Служебное имя вместо профессии | Нарушает требование пользователя | peer-supplement п.1 |
