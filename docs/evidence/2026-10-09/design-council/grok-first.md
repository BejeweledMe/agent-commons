Сборка пригодна для просмотра карт и настроек на широком desktop, но главный чат в этой сессии не готов к отправке, а уже на ширине около 1100 CSS px карта и чат не живут вместе. Ниже только то, что видно в evidence и подтверждается исходниками.

## 1. Область и реальные ограничения проверки

Проверены `brief.md`, `evidence/READY`, `capture-notes.md`, `steps.json`, `task-modal-geometry.json`, 25 accessibility-tree DOM и 25 PNG (`01`–`25`), плюс фронтенд `source/frontend/work/src` и контракт `source/docs/PRODUCT.md`. Отдельное приложение `source/frontend/gallery/src` в захвате не открывалось.

Ограничения, которые нельзя закрыть этим пакетом:

- Скриншоты и DOM сняты организатором в одной сессии Chrome на проекте Blizhe, порт 8794. Это не независимый браузерный прогон. Формы не отправлялись, агенты не запускались, скролл, drag и нагрузка не проверялись.
- PNG при viewport override содержат тёмное поле за CSS viewport. Это артефакт захвата, не overflow приложения (`capture-notes.md`).
- Точные контрастные отношения и пиксельные отступы не измерялись. Визуальные выводы сделаны по просмотру PNG; дословный текст сверен с DOM, а не с пересказом картинки.
- Населённая галерея результатов не показана: у Frontend выборка пустая.
- Клавиатурный обход целиком не выполнялся. Заметки фиксируют только Escape настроек и чата.

## 2. Сильные стороны

Карта остаётся на месте под модалками. Геометрия области карты до, во время и после task modal совпадает: `817.8×435.9` в `x=274, y=167` (`evidence/task-modal-geometry.json`). На PNG `02`–`07`, `09`–`11` граф агентов или задач виден под затемнением, а не размонтирован.

Модалки — настоящие `dialog` с общим ×, без закрытия по backdrop, с возвратом фокуса через `preventScroll`, чтобы не сдвигать карту (`source/frontend/work/src/components/Modal.tsx:8-23`, `74-76`). Заметки захвата подтверждают: Escape настроек возвращает фокус на «Настройки агента», Escape чата — на «Чат».

Четыре вкладки агента открываются и догружаются отдельно: «Основное» сначала «Загружаем полные настройки…» (`02`), затем поля (`03`); «Навыки», «Права», «Связи» (`04`–`06`) имеют свои tabpanel. Пустые связи и пустая галерея названы явно, а не оставлены пустым прямоугольником (`06`, `18`).

Оболочка читается: левый rail с именами ссылок, список проектов с disabled для недоступных workspace, вкладки «Задачи / Агенты», разделители панелей, RU/EN как `aria-pressed`. На карте задач зависимости и статусы различимы (`08`); EN-хром на `25` переведён («Tasks», «Map», «Fit», «New task»). У icon-кнопок карточек есть доступные имена в DOM (`01`, строки 95–103).

## 3. Реестр замечаний

**AC-01 · P1 · главный чат, все экраны `01`–`18`.** Наблюдаемо: «Доступность неизвестна», «Сообщений пока нет», «Отправить сообщение» disabled, рядом «Подготовить запуск». Влияние: правая рабочая колонка не принимает сообщение. Код подтверждает, что чип только читает `recipient_availability`, а Prepare run навигирует и префиллит, не запуская прогон (`ConversationPanel.tsx:117-129`, `221-225`; `main.tsx:688-689`). Рекомендация: развести unknown / inactive / no run и написать, что именно сделает кнопка. Компромисс: консервативный запрет отправки без живого получателя оправдан, непрозрачность — нет. Уверенность высокая.

**AC-02 · P1 · узкое окно, `19`–`20`, также `21`.** Наблюдаемо: при CSS около 1100×700 чат становится шторкой на всю высоту и закрывает карту; закрытие возвращает карту. Код: при `max-width: 1100px` rail и chat — absolute drawer, одновременно виден только центр (`styles.css:1395-1402`). Влияние: заявленная тройка «навигация + карта + чат» ломается уже на ширине ноутбука, не только на телефоне. Рекомендация: порог ниже или узкий docked-чат, а не полноэкранный drawer. Компромисс: drawer спасает 800 px, но 1100 px для этого продукта рано. Уверенность высокая.

**AC-03 · P2 · карточки агентов, `01`.** Наблюдаемо: фиксированные карточки, 8 icon-кнопок, одна текстовая «Связи», длинные имя и описание. DOM отдаёт полный текст, CSS режет identity в одну строку и meta в две (`board.css:90-95`; `title` только на имени и описании, `ProjectBoard.tsx:50-52`). Статус активности в этом снимке — «Свободна» / «Нужны вы», не отдельная причина неготовности. Влияние: с карты не видно, почему агент не берёт работу, без hover/title. Рекомендация: причина блокировки второй строкой или tooltip; часть действий увести в меню. Компромисс: равная высота 248 px нужна автолэйауту. Уверенность средняя по пиксельному обрезанию, высокая по плотности и CSS.

**AC-04 · P2 · «Дать задачу», `01`.** Наблюдаемо: кнопка disabled на всех видимых карточках, без причины. Код: disabled, если нет выбранной задачи, а не из-за готовности агента (`ProjectBoard.tsx:62`, `199`). Влияние: основной жест с карты выглядит сломанным. Рекомендация: disabled + пояснение «сначала выберите задачу» или открывать выбор задачи. Уверенность высокая.

**AC-05 · P2 · вкладка «Навыки», `04`.** Наблюдаемо и в DOM: combobox из `agent-llm-evals`, `web-frontend-engineering` и т.п. Код рисует сырой id (`AgentSettings.tsx:99`). В библиотеке те же методы подписаны по-человечески (`14`). Влияние: назначение навыка требует знания slug. Рекомендация: имя из каталога, id вторично. Уверенность высокая.

**AC-06 · P2 · футер настроек, `03`–`06`.** Рядом «Сохранить изменения» и «Обновить · сохранить черновик». Вторая кнопка вызывает `session.load(true)`, это перезагрузка с сохранением черновика, не запись (`AgentSettings.tsx:54`; ключ `agent_reload_keep`). Влияние: легко принять reload за commit. Рекомендация: «Обновить данные, не записывая». Уверенность высокая.

**AC-07 · P2 · права, `05`.** Опция «Автоматически · нужно подтверждение» при тексте, что автоматические действия всё равно требуют подтверждения (`i18n.json`, ключ `agent_grant_auto`). Влияние: нельзя предсказать, что сохранится. Рекомендация: одно слово состояния и одна фраза про effective grant. Компромисс: запрет тихого auto уместен. Уверенность высокая.

**AC-08 · P2 · настройки окружения, `16`.** «Рабочее пространство готово» одновременно с claude-builder: «Проверочный запуск не удался» и «Ещё не проверялось» у второго профиля. Влияние: ложное ощущение, что исполнители готовы к запуску, хотя чат как раз unknown. Рекомендация: сводка готовности не зелёная, пока обязательный probe упал. Уверенность высокая.

**AC-09 · P2 · детали задачи, `09`–`10`.** Сначала загрузка, затем стена текста ожидаемого результата без разбиения, плюс «Данные о свидетельствах устарели». Влияние: принятую задачу трудно проверить глазами. Рекомендация: критерии списком, длинный brief под disclosure. Уверенность высокая.

**AC-10 · P2 · 800 и 390 CSS px, `21`–`24`.** Заметка шага 22: после resize карточку агента удалось открыть только через «Показать всё». На 390 px виден в основном владелец и край карточек; задачи становятся вертикальным списком, граф зависимостей не читается. Влияние: карта как центр работы на узком окне не сохраняется. Рекомендация: после resize вызывать fit; на узкой ширине явный режим «список», а не обрезанный canvas. Уверенность высокая для 800 (заметка шага), средняя для причины обрезания на 390.

**AC-11 · P3 · найм, `07`.** Фокус сразу на «Закрыть», не на специализации; длинный select открыт сверху. Новая задача, напротив, фокусирует название (`11`, active input). Рекомендация: единый initial focus на первое поле. Уверенность высокая.

**AC-12 · P3 · rail и библиотека.** Rail icon-only 44 px, имена есть в accessible name, hover-tooltip в захвате не проверялись. Вкладки библиотеки в DOM склеены со счётчиком: «Роли32», «Навыки45» (`13`, `14`). EN-хром на `25` чистый, названия задач остаются русскими — это данные, не баг хроми. Уверенность высокая по DOM, низкая по визуальному зазору счётчика.

**AC-13 · наблюдение, не дефект · галерея `17`–`18`.** Loading, затем «В этой выборке пока нет сохранённых изображений или живых интерфейсов». Населённый preview не снят (`capture-notes.md`). Отдельный gallery-app в evidence нет.

Гипотезы, не выдаю за факты: контраст `--text-2: #b6b6b6` на `#252525` может быть тесным для мелкого 11 px; React Flow с пачкой кнопок на карточку может тормозить на большом проекте. Замер не делался.

## 4. Спорные решения

Модалка поверх карты, а не третья колонка, здесь оправдана: геометрия карты не прыгает, черновик не теряется от клика по backdrop. Цена — чат и навигация остаются в дереве под dialog; визуально они приглушены, фокус у диалога.

Два режима связей «Структура / Зависимости» полезны, если подпись на карте видна. На `12` масштаб 33%, и скриншот выглядит пустее DOM: в дереве задачи есть (PHOTO и другие). Это не пустой граф, но fit по умолчанию для структуры стоит проверить.

Иконки на карточке агента экономят высоту, но без постоянного текста действие узнаётся только по tooltip. «Связи» текстом рядом с icon-only рядом это подтверждает.

Порог 1100 px как drawer логичен для телефона и спорен для рабочего места разработчика: продукт сам описывает карту между навигацией и чатом (`PRODUCT.md`).

Сырые skill id и «автоматически, но с подтверждением» похожи на честный контракт с сервером. Для ежедневного UI это всё равно должен быть человекочитаемый слой поверх контракта.

## 5. План и приёмка

Сначала AC-01 и AC-08 вместе: готовность чата должна ссылаться на probe провайдера. Приёмка: при unknown видна причина и следующий шаг; кнопка не обещает запуск, если только открывает задачу; send остаётся disabled, пока получатель не active.

Затем AC-02 и AC-10: порог compact и fit после resize. Приёмка: на 1280 CSS px карта и чат видны вместе; на 800 px drawer не обязателен для попадания в карточку; после смены ширины агент остаётся в кадре без ручного «Показать всё».

Потом копирайт и плотность, без смены API: AC-05, AC-06, AC-07, AC-04, AC-03. Приёмка: навык выбирается по имени; вторичная кнопка не содержит «сохранить», если это reload; «Дать задачу» объясняет disabled; обрезанный статус имеет title с полным текстом.

AC-09 можно отдельно: ожидаемый результат длиннее N строк сворачивается. AC-11 — фокус найма на первое поле.

## 6. Вердикт

Для ежедневного разбора задач и агентов на широком окне сборка уже рабочая: иерархия, сохранение карты под модалкой, четыре вкладки настроек, пустые и loading-состояния сделаны аккуратно. Для ежедневного управления командой есть оговорки: в этой сессии главный чат нельзя отправить и причина не объяснена, готовность workspace спорит с упавшим probe, а совместная работа карты и чата пропадает с 1100 CSS px. Блокера уровня «экран не открывается» в пакете нет.
