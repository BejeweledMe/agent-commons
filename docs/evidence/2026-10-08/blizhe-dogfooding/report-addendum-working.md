## Восприятие дизайна и первого использования

**UI.** Тёмная тема спокойная, состояние нажатой RU/EN кнопки видно, основные действия выделены синим. Понятны отдельные разделы «Доска», «Задачи», «Библиотека», «Настройки». Из плюсов — явные критерии приёмки, задачи-предпосылки отдельно от компонентов, отдельное действие запуска и объяснение Fresh. Сообщение о долгом сохранении говорит не нажимать снова; форма блокируется. Наём PHOTO действительно создал одну роль и не запустил её.

**UI, граница 1042×467.** Верх экрана занят шапкой, широким status banner, поясняющим абзацем, панелью кнопок и технической строкой про брокер/checkout. При открытом найме сама доска оказывается почти целиком ниже/за панелью. Карта задач также начинается ниже первого экрана. Текст преимущественно мелкий, плотность высокая; это наблюдение именно в указанном окне, не мобильный аудит.

**Гипотеза.** Для первого владельца форма найма слишком рано требует понять разницу специализации, роли, воркера, runtime-профиля, модели, квалификации, Fresh и Context Pack. Раздел Advanced помогает, но рядом всё ещё стоят внутренние термины. Лучше начать с ожидаемой работы и рекомендованного доступного исполнителя, а техническую конфигурацию раскрывать по запросу. Не скрывать цену/лимиты и реальную готовность.

**UI/Операция.** Формулировка «роль создана» полезна, но toast от предыдущего действия остаётся во время нового сохранения. Наём PHOTO показывал Still saving, затем прошёл; точное время от начала до ответа не замерено. Повторный клик не посылался — кнопка была отключена, это не тест идемпотентности сервера. V22 снят уже после успеха; слово long-save в имени файла не доказывает кадр ожидания.

**Гипотеза UX-50, P2.** Нужен короткий маршрут первого использования «подключить папку → выбрать команду → сформулировать задачу → проверить среду → первый результат». Сейчас помощь разбросана между разделами; для восстановления после needs_operator пришлось изучать команды и исходники. Наблюдение одного технически опытного оператора не равно исследованию с новичками.

## Новые дефекты и предложения

- **UX-47, Операция/Код, P1 для Claude.** Статический preflight прошёл, но canary не начал модельную работу: provider initialization failed. Двух no-model измерений достаточно для конкретной причины: timeout5s прерывает `claude mcp list` на5.56s; диагностические15s позволяют ему закончить на6.34s. Продуктовый timeout не изменяли. В UI нет ясной команды исправления и кнопки повторного check run. Не утверждаем, что весь Claude провайдер неисправен.
- **UX-48, Операция/Код, P1.** CLI `task complete --artifact-ref …`, затем `task submit` без повторённого флага обнуляет refs. Оператор сделал именно эту ошибку; первый QA не нашёл13артефактов и завершился input-needed. Не перекладываем ошибку на UI. Предлагаем сохранять refs по умолчанию и показывать точное число доказательств/предупреждать перед независимым QA.
- **UX-40 повторён на TOOL.** После approved UI всё ещё просит «Запросить проверку»; кнопки приёмки нет. Supported CLI accept принял результат без переписывания QA. То же несоответствие мешает return/fix после changes_requested.
- **Положительное CAS.** Конфликт ревизии не затёр task draft, UI объяснил Reload task. Оператор скопировал draft, обновил задачу и восстановил текст; сам reload очищает поля, поэтому не заявляем автоматический merge.

## Расширение по поручению владельца

PHOTO создана в UI с зависимостью TOOL, отдельной backend-ролью и шестью AC. OpenAI Decisions — реальный dedicated API, официальная документация сохранена как входной пакет. Ключ не присутствует в isolated env; live smoke не заявлен. Отказ/таймаут/невалидный/неопределённый ответ оставляет pending. Face/liveness остаются отдельными воротами.

SEARCH создан как компонент и два дочерних независимых аудита. Claude выполнен через claude.ai на Opus5.5 medium, поскольку Commons qualification blocked, а Fable5.1 в браузере требует отдельные usage credits. Это явно не запуск Fable и не Commons broker run. Claude видел операторский пакет excerpts, Codex читает весь доступный repo: ограничения разной полноты входов сохраняем. Ответы ещё не превращены в принятую архитектуру и не означают готовность поиска.

За новое окно на этом срезе: восемь проектных прогонов (включая неудачные и текущий SEARCH-A), одна попытка Claude canary без начавшейся модельной работы, один браузерный первый ответ Claude. Продолжения после исходных трёх согласованы последующими разрешениями владельца, расширившего scope; старые stops и расходы не стерты.
