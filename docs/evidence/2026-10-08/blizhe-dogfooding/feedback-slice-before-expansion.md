- Отдельная операторская сессия; doctor; пять `artifact register`; `handoff create`; task take/start/complete/submit и review request. UI не предложил путь регистрации текстового BASE и передачи после исторического needs_operator. Исходный стоп не переписывался в success.

- `review list` и `delegation show` для чтения реального вердикта, затем `task accept`, поскольку UI предлагал повторный review. Новый review не создавали.
- Чтение `worker_eligibility.py`, CLI reference parser, handoff/review/task commands, `ui/launch.py`, `services/execution_plan.py` и scoped MCP terminal contract потребовалось для понятного и корректного продолжения. Исходники Commons не изменяли.
- Проверка TOOL через CLI, когда после смены проекта UI показывал проверку доступа; чтение отчёта агента, финальные hash/Git/doctor и owner snapshot.
- Два ошибочных вызова оператора (`task show`, `doctor --read-only`) получили `No such command/option`; правильные формы — task list и глобальный `--read-only doctor`. Это ошибки использования CLI, не дефекты продукта.

## 5. Что сохранить при упрощении

Сохранить независимую сессию QA и точную привязку verdict к ревизии; разделение canonical outcome, provider exit, review и acceptance; блокировку зависимостей до принятия BASE; проверку одного пишущего воркера; явные лимиты запуска; immutable версии специализаций. Custom специализация не должна расширять permissions.

Сохранить пять стадий доставки с явным подтверждением чтения и ответом: на TOOL это дало реальное доказательство, что новый запуск для уточнения не нужен. Сохранить честные сообщения о потере черновика при reload, отсутствии результатов галереи и недоступных проверках.
