## 3. Информационная архитектура и глоссарий первого уровня

Принцип: **пользователь видит роли людей и результаты, а протокол — по запросу.**
Canonical-значения не переводим и не переименовываем в данных; меняем только
слова первого уровня и добавляем гloss (контракт: «canonical value — gloss»).

| Внутреннее понятие | Слово первого уровня (RU / EN) | Где показывать протокольное имя |
|---|---|---|
| Project | Проект / Project (папка — в меню проекта) | Меню проекта, Settings |
| Skill / Group | Навык, группа навыков | Library → Skills |
| Specialization | Роль / Role | Library → Roles |
| Agent instance (+profile, provider, model) | Исполнитель / Worker: «Codex Frontend» | Расширенные настройки исполнителя |
| Blueprint | Шаблон команды / Team template | Library → Templates |
| Task | Задача | везде |
| Run / delegation attempt | Запуск / Run («попытка №2») | Инспектор → Запуски |
| Output / live preview | Результат / Result | Кнопка «Результаты» |
| Review | Проверка / Check (заключение проверяющего) | Инспектор → Проверка |
| Accept | Принять работу / Accept work | Карточка решения |
| Evidence complete | «Данные полные» — никогда не «готово» | Только в technical details |

Слова, которые **уходят с первого уровня**: canonical, evidence, readiness,
revision, qualification, canary, delegation, ledger, snapshot. Они остаются в
раскрытии «Технические детали» и в CLI.

Навигация остаётся четырёхчастной (Work / Agents / Library / Settings), но Work
получает внутренние вкладки: **Сейчас · Карта · Все задачи**. Это не новые
canonical-состояния, а представления над существующими фильтрами.

## 4. Два основных пути

### 4.1 От папки до первого результата (целевой сценарий)

1. **Подключить папку** → диалог как сейчас, плюс после успеха: экран «Проект пуст» с двумя кнопками: «Выбрать шаблон команды» / «Создать задачу вручную». (Сейчас принудительный переход в Library → Blueprints без объяснения.)
2. **Шаблон** → обзор: какие роли, какие задачи, зависимости; выбор исполнителя для каждой роли (сначала роль, потом доступные исполнители с чипами возможностей). Кнопка «Создать роли и задачи».
3. **Результат применения** → «Создано… Ничего не запущено.» → «Начать первую задачу».
4. **Инспектор задачи** → карточка «Запуск»: исполнитель, лимит времени попытки, что он сможет (чипы), кнопка «Запустить». Отказ — типизированный, с одной понятной причиной и одним действием.
5. **Экран «Сейчас»** → задача в колонке «В работе» с исполнителем и таймером; сообщение в чат с чипом доставки.
6. **Результат** → кнопка «Результаты (1)» → карточка «Последний результат» с превью (изображения инлайн, frontend-preview — ссылкой в отдельный origin).
7. **Проверка и решение** → карточка решения: «Проверка одобрена (Claude Reviewer, версия 3) · Нужно ваше решение: Принять / Вернуть с замечанием».

### 4.2 Ежедневный контроль

Открыл проект → «Сейчас»: три колонки **Нужно от вас · В работе · Дальше**.
Каждая карточка отвечает на три вопроса: что, кто, что мешает. Клик → инспектор
с тем же порядком. Карта и полный список — по вкладкам, для расследования.

## 5. Матрица состояний интерфейса

Правила (из контракта): состояние меняется только по ответу сервера; неопределённый
исход хранит исходный запрос и ключ; повтор — только идентичный.

| Стадия | Состояние | Что видит пользователь (RU) | EN | Можно ли продолжать другое |
|---|---|---|---|---|
| Сохранение | saving < 2 с | Кнопка «Сохраняем…», форма заблокирована | Saving… | Да (навигация, чтение) |
| Сохранение | saving 2–8 с | + таймер «3 с», подпись «Большой проект: запись может занять время» | Large project: this can take a moment | Да |
| Сохранение | saving > 8 с | «Всё ещё сохраняем. Повторный клик не нужен» | Still saving. No need to click again | Да |
| Сохранение | saved (confirmed) | Тихое подтверждение у формы + обновлённые данные с сервера | Saved | Да |
| Сохранение | failed | «Не сохранено: <причина>. Повторить то же действие» | Not saved. Retry the same action | Да |
| Сохранение | uncertain | «Результат неизвестен. Проверить состояние / Повторить с тем же ключом». Форма хранит исходный текст | Result unknown. Check state / Retry identically | Да, кроме этой формы |
| Обновление | refresh failed | «Сохранено, но не удалось загрузить свежие данные. Обновить (действие не повторится)» | Saved, but the latest data could not be loaded. Refresh does not repeat the action | Да |
| Смена проекта | pending write in other project | Бейдж на строке проекта «Сохраняется…»; результат покажется при возврате | Saving in background | Да |
| Сообщение | recorded → queued → fetched → acknowledged → replied | Пять шагов прогресса; текущий выделен; отсутствие ack — «ещё не подтверждено прочтение», не галочка | Recorded / Queued / Fetched / Read confirmed / Replied | Да |
| Сообщение | адресат без прогона | Чип «Нет активного запуска» + «Подготовить запуск» | No active run · Prepare run | Да |
| Запуск | preparing / running / exited | Таймер, лимит попытки, исполнитель; «завершился: результат отправлен на проверку» | Run exited: result submitted for check | Да |
| Запуск | needs_operator / input_needed | «Исполнитель остановился и ждёт вас: <вопрос>»; ответ — новым запуском (headless не возобновляет) | Worker stopped and needs you | Да |
| Результат | latest / earlier / preview expired / unavailable / awaiting check | Разделённые подписи (B-09) | Latest / Earlier version / Preview expired / Address unavailable / Awaiting check | Да |
| Проверка | approved / stale / rejected | «Одобрено для версии N» · «Проверка устарела: задача изменилась» · «Возвращено: <замечание>» | Approved for revision N / Check is outdated / Returned | Да |
| Решение | accept available | Карточка: результат, заключение, «Принять работу» (единственный зелёный акцент после принятия) | Accept work | — |
| Ошибка окружения | setup / provider | «Не настроено» · «Проверка устарела» · «Ошибка провайдера: <bounded stderr>» — три разных состояния | Not configured / Check outdated / Provider error | Да |

## 6. Визуальное направление

Цель — цельность и иерархия, а не смена гарнитуры. Два направления на одном
наполненном контенте (кадры V07, V08, V09, V11 из handoff):

- **Направление A «Спокойная панель управления»**: текущая тёмная схема, консолидированные токены, крупнее только заголовки карточек и состояния, цвет — только для 4 семантик (нужно от вас / в работе / принято / ошибка).
- **Направление B «Документ работы»**: светлая тема по умолчанию, тёмная как вариант; больше воздуха, карточки без рамок, состояния — текстовые чипы. Требует light-палитры (сейчас её нет).

Общее для обоих:

| Область | Сейчас | Предложение |
|---|---|---|
| Цвет | 19 токенов + 118 hex | Семантические токены: `surface/1..3`, `text/1..3`, `border/1..2`, `status/attention`, `status/active`, `status/accepted`, `status/error`, `accent`. Правило lint: hex только в `:root`. |
| Отступы | 8/12/14/16/18/20/28 px ad hoc | Шкала 4·n: 4, 8, 12, 16, 24, 32, 48 |
| Типографика | системный стек, размеры разрозненно | Шкала 12/13/14/16/20/24; line-height 1.45 для текста, 1.2 для заголовков; max-width 68ch для абзацев |
| Статусы | цвет и текст смешаны | Всегда текст + иконка; цвет как дублирование. Зелёный — только «принято». |
| Компоненты | feature-prefixed one-off классы | Базовые: Card, StatusChip, Stepper (доставка), DecisionCard, ActionBar с состояниями из раздела 5 |

## 8. Решения, которые нужны от владельца до реализации

1. **Домашний экран.** Согласиться, что «Сейчас» (три колонки) заменяет граф по умолчанию, а граф становится вкладкой. Альтернатива: оставить граф, добавить панель «Нужно от вас» сверху.
2. **Понятие «волна/цель».** Derived от применения шаблона (дёшево, неточно для ручных задач) или новое canonical поле (точно, требует ADR и миграции).
3. **Визуальное направление.** A (тёмная, консолидированная) или B (светлая по умолчанию). Влияет на объём фазы 3 вдвое.
4. **Локали в авторинге.** Разрешить одноязычный шаблон с автокопией во вторую локаль или сохранить строгую двуязычность.
5. **Лимит времени проверочного запуска.** Показывать в UI фактическое значение из snapshot или задать продуктовый дефолт и его объяснение.
6. **Starter packs.** Скрыть в Advanced или удалить после миграции.
7. **Пороги ожидания.** Принять 2 с / 8 с как пороги подсказок и p50 ≤ 1 с / p95 ≤ 3 с как цель после профилирования, либо назначить свои.
8. **Инструментирование.** Разрешить локальные (не отправляемые наружу) счётчики: повторный клик по тому же действию в течение 5 с, retry после uncertain, переходы в CLI. Без них метрики раздела 9 не измерить.
