### CLI fallback и обращения к документации

- Для точной границы использованы read-only git rev-parse/status/log и CLI --version, поскольку точный commit не показан на проверенных экранах. Это отдельный **CLI fallback для диагностики версии**, а не управление пользовательским сценарием через CLI.
- Для оценки reload прочитаны README:123–124, service-library:89–91 и прежняя запись UX-15. Без этой сверки очистку черновика можно было ошибочно назвать регрессией.
- Запись отчёта и копирование скриншотов выполнялись файловыми инструментами как оформление результата. Пользовательские переходы, черновик и галереи — через UI.
- Два ожидания CUA завершились `Playwright selector deadline exceeded`. После reload ожидался русский textbox, но приложение вернулось на EN; свежий DOM показал исправно открытую пустую форму. При переходе в другой проект свежий DOM позже показал загруженный экран. Эти таймауты не названы отказом Commons.

Не проверены независимый QA BASE, приёмка, реализация TOOL и его проверка; успешная загрузка/доставка вложения; custom QA-reviewer роль; операторская регистрация/handoff; непустая галерея результатов этого прогона. Код BASE helper прочитан как результат, но не запущен повторно оператором: сверка hashes не равна независимой проверке содержания. Все пять файлов результата оставлены как создал агент. Исходники обоих приложений не редактировались; HEAD не менялся; никаких commit/push/PR/Linear mutations оператором не выполнялось.

**Подготовленное продолжение для решения владельца:** разрешить оператору зарегистрировать готовые точные BASE-файлы и handoff штатными командами как документированный CLI fallback, затем подобрать через UI совместимую независимую QA-роль. Не повторять BASE вслепую. После корректной передачи использовать оставшиеся три прогона на QA(BASE) → TOOL → QA(TOOL), каждый до 60 минут. Приёмка только по независимому вердикту. До разрешения на выход из нового needs_operator эти действия не выполнены.

Снимки V15–V20 EN/RU дополняют manifest. V15 RU — реально наблюдавшееся сохранение, V15 EN — состояние после успеха, а не тот же busy-frame. Кадры результатов/приёмки не имитировались, поскольку этот путь не был достигнут.
